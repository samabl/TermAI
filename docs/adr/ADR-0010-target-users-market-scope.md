# ADR-0010：目标用户与市场范围

- 状态：Accepted
- 日期：2025-01-01
- 决策者：Orchestrator（综合 10 角色评审）
- 关联：AR-15；DC-06、DC-07；HARNESS §1.1、§1.3、§8.2、§10.12、§11（OQ-19）

## 背景与问题
1. 市场诱惑：零基础学终端是最大的增量教育市场，课程式引导与欢迎向导是行业默认的转化手段。
2. 产品公理冲突：A2 要求终端本命是延迟、正确性、可脚本化；A1 要求终端是信任基础设施——欢迎向导与教学模式会直接违背「首屏即输入、零弹窗」的体验目标。
3. 量化冲突：§8.2 要求 **TTFC ≤3 分钟且零弹窗**；教学式引导天然引入弹窗、步骤与阻塞。
4. 定位风险：一旦面向初学者，产品会被迫在默认行为上做「安全但啰嗦」的取舍，进而损害 Primary 用户的关键路径。
5. Persona 已明确：Primary = SRE/平台工程师 + 高级软件工程师；Secondary = 数据/AI 工程师 + CLI 重度用户。

## 可选方案（至少 2 个，含被否决项）
| 方案 | 主张方 | 否决 / 采纳理由 |
| --- | --- | --- |
| A 面向零基础教学市场，内置课程式引导与欢迎向导 | 增长派 | 否决（Anti-features §10.12）。与 TTFC ≤3 分钟零弹窗冲突；稀释 Primary 体验 |
| B 双市场并存，用模式切换区分 | 折中派 | 否决。模式切换带来两套 IA、两套文档与两套默认值，维护成本翻倍且定位模糊 |
| C 只做专业市场：Primary = SRE/平台 + 高级工程师，不做教学模式 | Orchestrator | **采纳**（AR-15） |

## 决策
1. **Primary = SRE/平台工程师 + 高级软件工程师**；Secondary = 数据/AI 工程师 + CLI 重度用户/终端爱好者。
2. **不做零基础教学市场、不做课程式引导、不做欢迎向导**；**首屏即输入、零弹窗**（AR-15）。
3. 零配置即是一条合格的普通终端：渐进披露为主，AI 能力不阻塞基础使用（与 AR-16 的入口顺序一致）。
4. 明确不做（DC-06 / §10）：通用聊天、代码编辑器/IDE、自然语言 Todo、自研 shell 语言。
5. 北极星 = **Accepted AI Actions per WAU ≥5（上线 6 个月）**；护栏 = 危险命令误执行率 <0.5%、L2/L3 未审批执行 = 0、AI 关闭时核心可用性 100%（DC-07、§1.4）。
6. 治理：成立独立 TSC（3 年内 BDFL + 公开 ADR 过渡），保证市场范围变更不被单方推动（OQ-19，P0）。

## 理由
1. 专业市场的付费与留存质量更高：D7 ≥40% / W4 ≥20% 的目标只能由高频终端用户贡献（§1.4）。
2. 教学市场的获客红利需要产品让步（引导、简化默认值），而这些让步恰好摧毁 Primary 用户最在意的确定性与速度。
3. 拒绝教学模式不等于拒绝新用户：零配置可用 + 渐进披露已能让有基础的用户自助上手。

## 后果（正面 / 负面 / 需要接受的代价）
- 正面：定位清晰，默认值可以「专业优先」；TTFC 与零弹窗可验收；文档与 IA 保持单一。
- 负面：放弃最大教育市场，规模故事变难（增长反方）；早期用户增长更多依赖口碑与社区。
- 需要接受的代价：
  1. 必须用产品指标而非市场规模讲故事（NSM、留存、护栏指标）。
  2. 新人上手完全依赖文档质量与默认值设计，必须投入 glossary / docs/spec 的持续维护。
  3. 所有营销材料不得暗示「零基础也能用」，避免预期错配。

## 反方记录与复议条件
- **反方（增长，保留原文）**：放弃最大教育市场，规模故事变难；课程式引导是被验证的高效转化手段。
- **复议触发条件**：若**留存实验证明情境化教学显著提升 Secondary 转化**，可作为独立「**场景模板**」而非教学模式回归（AR-15 明文）。
- 约束：回归形态不得引入欢迎向导与开机弹窗；不得破坏 TTFC ≤3 分钟且零弹窗的门禁（§8.2）。
- 不可放宽：不内建课程体系、不做零基础教学模式（§10.12）。
