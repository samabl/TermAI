## 1. 背景与问题

### 1.1 本 ADR 要更正的第一个前提：D-1 不是「两条 §8 条款谁管辖 esctest」

HARNESS 对同一件事给了两句强度不同的话：

- §7（P0 出口）：**「vttest + esctest 全通过」**。
- §8.1-1（门禁）：**「vttest / esctest / kitty 套件 100%；xterm 兼容用例 ≥99%（差异登记在案）」**。

`docs/plan/p0-open-decisions.md` 的 D-1 据此提出「当 esctest 的失败同时触犯这两条时，哪一条管辖」，并建议**读法 B**（子集 + 按 K-04 登记差异）。

**本轮核实（读 `docs/spec/kernel/01-vt-conformance.md` §5 与 §2 K-01，原文）**：这**不是一个未决问题**——kernel/01 早已把两句话各自绑定到**两个不同的套件**：

| 验收项 | 套件 | 判据（kernel/01 §5 原文） |
| --- | --- | --- |
| **V-01** | vttest | **100%**（`R_strict=1, X=0`） |
| **V-02** | **esctest** | **100%**（§8.1-1、§7 P0；`R_strict=1, X=0`） |
| **V-03** | kitty 套件 | **100%** |
| **V-04** | **xterm 兼容用例**（ctlseqs 每条目 ≥1 用例，≥2000 条 + 真实语料 ≥20%） | **`R_gate ≥ 0.99`**，且每条差异在登记表内 |

而 K-01 明文写着：「**100% 套件要求 `R_strict=1` 且 `X=0`；xterm 套件要求 `R_gate ≥ 0.99` 且 `|X|` 受上限约束（OQ-VT-04）**」。

**因此 §8 的「≥99% + 差异登记」管辖的是 V-04（xterm 兼容**语料**），不是 esctest（V-02）。** D-1 把 V-02 与 V-04 合成一个套件（「esctest 本身就是 xterm 一致性套件」），是本条要更正的**前提错误**。

**结论（否决读法 B）**：对 esctest 适用 K-04 的差异登记，意味着 `X>0`，**直接违反 K-01 对 100% 套件的 `X=0` 要求**；采纳它等于**放宽 §8.1-1**，按 AGENTS §5 需要 TSC 批准与基准数据——而 TSC 未成立（C1）。**故本 ADR 不采纳读法 B**。这不是新决策，而是**回到 kernel/01 的既有明文**。

**后果（如实记录，且对 E-P0-1 不利）**：esctest 的 **259 条失败全部是硬缺口**。唯一合法的分母削减是 K-01 允许的 **`S_cap`：套件 manifest 的静态能力前置**（例如 `graphics.sixel`），**禁止运行时或人工 skip**。因此 D-2/D-3 的问题形状也随之改变（见 1.2/1.3）。

### 1.2 D-2：颜色查询的问题不是「记在哪张表」，而是「是否声明能力缺失」

`OSC 4 / 10 / 11 / 12`（颜色查询/设置）在 `kernel/01` §3.5 的「v1 必须 / 可选 / **永不**」三类里**零命中**（第 226 轮核实；本轮复核仍为零）。我们目前一律不应答，esctest 的 **47 条**颜色族用例因此失败（`docs/audit/esctest-failing-index.md` 的 `ChangeColor*` / `ResetColor*` 族）。

在 1.1 的结论下，「不应答」**不能**靠 K-04 差异登记收口；它要么是**一项声明的能力缺失**（`S_cap`），要么是**必须实现的缺陷**。

### 1.3 D-3：设备身份同理，且方向被 oracle 钉死

esctest 以 **`--expected-terminal xterm`** 运行（缺该参数会得到伪失败，见运行手册 §2）。在 V-02 要求 `X=0` 的前提下，`DA` / `DA2` / `DECID` 这 **5 条**（`DA2Tests.test_DA2_0`、`test_DA2_NoParameter`、`DATests.test_DA_0`、`test_DA_NoParameter`、`DECIDTests.test_DECID_Basic`）**不可能靠「登记差异」通过**：要么应答与钉定 xterm oracle 一致，要么恒定红。

### 1.4 D-4：§8.2 可靠性测量的归属与报告口径

AR-26 第 4 条要求 **sessiond 重建 P95 ≤2s / P99 ≤5s**，而 `kernel/06` 全文没有「重建 / reconnect」——§8.2 的时序测量**没有规定的归属、格式与判定人**。同时它**绝不能**进 `tools/bench/registry.mjs` 的 `SECTION5_MAPPING`：该表是 HARNESS §5 十九行的**逐字转录**，由门禁 B1/B3 每次从文档重新解析比对；加一行既是假转录、也不会被验证。

### 1.5 H12 / H13：D-6 留下的两个口径问题

- **H12**（输入字节等价）的 `governed` 是 **`partial`**，仓库里没有任何地方解释它相对 `yes`/`no` 的含义。
- **H13**（安装包，`governed: yes` 且 `machine: none`）与 `B7` 的张力：B7 的判据是「**非参考机上不得产出 gating 数字**」，而 H13 是**门禁行**却**不需要参考机**（`check.mjs` 的注释已写 `// package bytes: not a machine gate`）。

## 3. 决策（可执行结论）

### D-1｜esctest 的判定域 = kernel/01 V-02，`R_strict=1 且 X=0`

1. **esctest 不存在「登记差异通过」这条路**。其失败只有两种处置：**修**（实现）或**由 `S_cap` 静态能力前置排除**（且必须写进套件 manifest）。
2. **xterm ≥99% + 差异登记**只适用于 **V-04**（ctlseqs 派生 + 真实语料），差异上限仍受 **OQ-VT-04**（全局 ≤25、单 minor ≤10）约束。
3. **E-P0-1 的状态不变、且口径收紧**：**未判定**；当前 259 条 esctest 失败按「硬缺口」计数，**不得**以任何差异表豁免。
4. **禁止**在任何报告里把 esctest 的通过率写成「(P+X)/…」的门禁口径；esctest 只报 `R_strict`（K-01）。

### D-2｜`OSC 4 / 10 / 11 / 12`：v1 不实现、不应答，并明文登记

1. 在 `kernel/01` §3.5 的「永不（v1）」一侧**显式新增**这四条（当前是零命中，属于**默认沉默**而非登记）。
2. 在 `suites.toml`（或等价套件 manifest）登记**静态能力前置**（建议能力名 `color-query`），使 esctest 的颜色族用例按 K-01 的 `S_cap` 排除；**不得**用运行时/人工 skip。
3. **不得**在未实现颜色渲染前应答调色板（AR-20）。渲染可用后是否应答，作为一个**新**决策。

### D-3｜`DA` / `DA2` / `DECID`：必须实现，且与钉定 oracle 一致

1. `csi_dispatch` 增加 `CSI c`（DA1）、`CSI > c`（DA2）、`CSI ? c`（DECID，DA1 的过时别名）；`vte_adapter` 的 `csi_known` 对 `c` 的计数与行为**必须一致**（当前只计数不实现，是已知不一致）。
2. **应答必须与钉定 xterm oracle 逐字节一致**——esctest 在 `--expected-terminal xterm` 下断言 xterm 的应答，而 V-02 要求 `X=0`。**本 ADR 不冻结字节值**：本环境取不到 xterm 实现（ADR-0015 P3「未知即拒绝」/ 网络受限），字节值由实现轮**在钉定 oracle 上采证**后写入 `kernel/01` §3.5 与本 ADR 的勘误，并加一条 conformance 用例钉住它。
3. **诚实义务（AR-20）**：`DA1` 所声称的每一位都必须有**对应实现**；oracle 声明了而我们未实现的位，是**待修缺陷**，不是「可以跟着声称」的许可。该义务由新增 conformance 用例检查（声称集 ⊆ 实现集）。
4. **`TERM_PROGRAM=TermAI` 继续如实自报**（K-10 的另一半），`TERM=xterm-256color` 不变。

### D-4｜§8.2 可靠性时序测量归 `kernel/06` §3.10 + `tools/bench` 的独立登记

1. `kernel/06` **新增 §3.10「可靠性时序测量（§8.2）」**（放在 §3 详细设计的延续位置，**不是** §8 Open Questions 之下）；内容 = sessiond 重建 P95/P99 的测量定义、Run 定义、机器绑定、自检与报告口径。
2. 复用既有契约：`bench-report` schema（§3.7）、机器指纹（§3.4）、NON_GATING 语义（ADR-0014）、AR-27 可复现性自证。**机器绑定与 §5 相同**：无 RM-A/RM-C → `NON_GATING`/`INCONCLUSIVE`，不得成为门禁。
3. **登记表独立**：新建 `RELIABILITY_MAPPING`（`tools/bench/reliability.mjs`），**不得**向 `SECTION5_MAPPING` 增行（B1/B3 的逐字转录校验只覆盖 §5 的 19 行）。`B1/B3` 的转录范围不变。
4. **判定人**：当前无 TSC；在 `B7` 的机器绑定判据下，本机一律 `INCONCLUSIVE`。

### D-5｜H13 与 B7：`gatingNumbersProduced` 只计**机器绑定**的门禁数字

1. 一个值是「gating 数字」当且仅当它**声称参与门禁判定**（`gating: true`）**且**其登记的 §5 行由参考机判定（`machine ∈ {RM-A, RM-C}`），**或**该 metric 未绑定到任何登记行（无法证明它不是机器绑定 → **fail-closed，计入**）。
2. **`machine: none` 的行不计入**：`H13`（安装包，`governed: yes`）与 `H17/H18/H19`（`governed: no`）都不产生机器绑定的门禁数字。B7 的「非参考机零 gating 数字」由此**只约束 §5 的性能门禁**，与 ADR-0014 铁律 5 的原意一致。
3. **但 `governed: no` 且 `machine: none` 的行仍不得声明 `gating: true`**（那不是门禁，声明为门禁是假的）——该情形继续由 `B8` 的行绑定判为违规（即第 255 轮实现里那条规则收窄为 `machine==='none' && governed==='no' && gating===true`）。

### D-6｜H12 的 `governed: partial` 含义

`partial` = **测量方法由 kernel/06 承载（§3.6 D0 字节等价自检 + §3.2 补充 5），而语料与判定车道属于 kernel/05 与 G1/G2**：H12 的值只在 **L0 parser 车道**可判（AR-25 第 1 条），本机没有全语料回放，因此它**不是** D-6 的「机器无关可直接取值」行。此含义写入 `registry.mjs` 的 H12 注释与 `kernel/06` §3.9 的对应行。

## 4. 理由

1. **A1（终端是信任基础设施）**：D-1 拒绝「用差异表把 259 条失败合法化」，D-2 拒绝在无渲染时声明调色板，D-3 要求 DA1 的声称集 ⊆ 实现集——三项都在**收紧诚实边界**，而不是放宽门槛。
2. **A2（延迟、正确性、可脚本化）**：D-3 选择兼容身份，是因为基础设备查询的兼容性是入场券（K-10 同一逻辑）；D-2 选择显式不实现，是因为**兼容性不能靠撒谎获得**。
3. **可判定性**：D-1 让 E-P0-1 的分母口径唯一（两个套件、两个判据）；D-4 让 §8.2 有归属格式而不污染 §5 的逐字转录；D-5 让 B7 的判据从「恒真」变成「只约束机器绑定」。
4. **不动历史**：本 ADR 不采纳任何 §5/§8 放宽，因此不需要 TSC；它更正的是 `p0-open-decisions` 的一个**前提**（两套件被合并），依据是 kernel/01 的原文。

## 5. 后果

### 正面
- D-1 关闭后，E-P0-1 的剩余工作形状**变清楚且更严格**：259 条不是「待登记」，而是「待修或待 `S_cap` 声明」。
- D-2/D-3/D-4 各有唯一结论与落点；D-5 让 B7 的第三条判据真正生效且语义正确。
- §8.2 有了归属，且**不会**污染 §5 的逐字转录（B1/B3 不受影响）。

### 负面（必须接受的代价）
1. **E-P0-1 更难达成**：esctest 100% + `X=0` 意味着颜色族（47 条）不能靠差异表消失——只能声明能力缺失（`S_cap`）或实现。**声明能力缺失本身是成本**：它要写进套件 manifest，并在未来实现颜色渲染时撤销。
2. **D-3 依赖 oracle 采证**：本环境取不到 xterm 实现，字节值只能推迟到有 oracle 的环境，因此 D-3 在本机**不能完全关闭**（只能关闭「政策」）。
3. **D-4 的判定人仍缺**（C1/TSC），因此 §8.2 的测量在本机一律 `INCONCLUSIVE`。
4. **治理程序未走完**：ADR README §4.3 的两-maintainer + 7 天公示不可执行；本 ADR 的效力来自 Orchestrator + 项目所有者指示，TSC 成立后应追认。

## 6. 反方记录与复议条件

- **反方（务实派，对 D-1）**：读法 B 让 P0 有机会通过，坚持 100% 会让 P0 长期不可达。
  **驳回理由**：**「让门禁可过」不是裁决口径的理由**；且 B 需要 TSC 批准一次 §8 放宽，而 TSC 未成立（C1），所以 B 在当前治理下**本就不合法**。可变通的路是 `S_cap`（K-01 允许的静态能力前置），而不是差异表。
  **复议条件**：若成立 TSC 且其以基准数据批准 §8.1-1 的判定域变更，可重开；在此之前不得以任何形式把 esctest 的失败记为 xfail。

- **反方（兼容派，对 D-2）**：不应答会让 shell/编辑器拿不到调色板，影响真实应用。
  **驳回理由**：我们**没有颜色渲染**，报一套调色板是 AR-20 禁止的无法自证声明；且这些是**查询**序列，应用会退化但不会崩溃（与「终端尺寸查询」不同类）。
  **复议条件**：颜色渲染落地后（WS-03/04），以「所报调色板与渲染结果逐项一致」为证据重开。

- **反方（自研派，对 D-3）**：报 xterm 身份是「假装」，违反 AR-20。
  **驳回理由**：AR-20 禁止的是**无法自证的能力声明**；DA1 的兼容身份由 V-02 的通过率与「声称集 ⊆ 实现集」用例共同作证，且 `TERM_PROGRAM=TermAI` 如实自报产品身份（K-10 已冻结的同一做法）。
  **复议条件**：若出现「DA1 声称的某项能力长期无法实现」，则必须**从应答中移除该位**（而不是保留它），并重新评估 V-02 的可达性。

- **反方（成本派，对 D-4）**：§3.10 + 独立登记是又一套要维护的东西。
  **驳回理由**：不建独立登记，就只能往 `SECTION5_MAPPING` 加行——那会破坏 B1/B3 的转录校验并把 §8.2 混进 §5。复用 schema 与指纹的边际成本小于分叉成本。
  **复议条件**：若 `tools/bench` 的 `RELIABILITY_MAPPING` 与 §5 的判定逻辑出现实质分叉（两套「有效测量」定义），应合并或撤销。
