# ADR-0002：AI 运行时与内核的边界三分法

- 状态：Accepted
- 日期：2025-01-01
- 决策者：Orchestrator（综合 10 角色评审）
- 关联：AR-03、AR-17；DC-15、DC-21、DC-22、DC-26、DC-28、DC-29；HARNESS §4.1、§4.4、§0.4

## 背景与问题
1. 三方冲突：04 主张「AI 不得出现在 PTY→像素关键路径，必须是 sessiond 之外的消费者」；07 主张「AI 绝不进内核，只消费结构化事件」；10 主张「Agent Runtime 是一等内核组件，不得做成插件」。
2. 关键混淆点：把**产品属性**（是否第一方、是否默认可审计）与**实现属性**（是否同进程、是否链接内核）混为一谈。
3. 硬约束：内核不得依赖 AI、不得依赖网络、不持有网络句柄；AI 关闭时终端的可用性必须 100%（§1.4 护栏）。
4. AR-17 同时要求 AI 价值排序为「故障诊断 > 上下文感知命令生成 > 大规模运维」，决定了 Agent Runtime 必须能稳定读取诊断所需的完整结构化上下文。

## 可选方案（至少 2 个，含被否决项）
| 方案 | 主张方 | 否决 / 采纳理由 |
| --- | --- | --- |
| A Agent 作为第三方插件 / 可选安装 | 07 的强隔离倾向 | 否决。无法保证默认集成、版本一致与可审计，违背「AI 一等公民」（DC-01） |
| B Agent Runtime 作为内核进程内组件 | 10 | 否决。内核将链接 AI SDK 与模型凭据，热路径与空闲预算被污染，违反 §0.4 第 1 条 |
| C 三分法（产品层一等 / 进程层独立 / 契约层版本化） | Orchestrator | **采纳**（AR-03） |

## 决策
1. **产品层**：Agent Runtime 是**第一方一等组件**——随客户端同版本发布、默认集成、可审计、非插件（采纳 10 的安全底线）。
2. **进程层**：运行在**独立进程** termai-agent + watchdog；内核不链接任何 AI SDK、不持有网络句柄、AI 关闭时零开销（采纳 04/07）。
3. **契约层**：内核只承诺「结构化 Session Log + 版本化能力协议」；AI 通过**只读订阅 + 受控写入**访问 Context，**写 stdin 必须显式授权**。
4. 通信走 termai-ipc（二进制 + 版本/能力协商），JSON-RPC 仅用于调试与第三方入口（DC-22）；热路径禁用 JSON/gRPC（AR-04）。
5. 模型路由与隐私：混合路由、BYO-Key 直连为一等公民、本地分类 P95 <50ms、云端诊断首 token <3s（DC-29）；工具 ABI 自研并兼容 MCP，MCP 独立进程沙箱 + Policy Engine 二次校验（DC-26、DC-28）。

## 理由
1. 「一等组件」是产品与安全属性，「进程内」是实现属性；两者不可混谈。三分法同时满足 10 的安全底线与 04/07 的边界要求。
2. 独立进程让「AI 关闭时内核零开销」可被门禁度量（对比 AI 开/关的 P95），而不是靠承诺。
3. 只读订阅 + 受控写入使「能力与意图分离」落地：模型产出结构化意图，命令由确定性执行器构造（§6.2 规则 1/2）。

## 后果（正面 / 负面 / 需要接受的代价）
- 正面：内核可独立测试与 fuzz（DC-37）；AI 可崩溃/重启而不影响会话；BYO-Key 与离线路径清晰。
- 负面：跨进程 IPC 带来序列化与握手成本；调试跨进程链路更复杂；诊断延迟预算是端到端而非单进程内。
- 需要接受的代价：
  1. 必须维护一套版本化 capability 协议，破坏性变更需协商且兼容窗口 ≥2 个 minor（AR-04）。
  2. 三类「会话」（PTY Session / Agent Session / Workspace）必须命名分离，禁止混称（DC-03）。

## 反方记录与复议条件
- **反方（07，保留原文）**：硬隔离不是目的本身；若能在零开销前提下提高集成度（更少 IPC、共享上下文快照），集成度可重评。
- **复议触发条件**：同时满足——(a) AI 关闭时 P95 时延劣化 <1%；(b) 无共享地址空间（内核仍不链接 AI SDK）。
- 复议不可放宽：内核不得依赖网络、不得持有模型凭据、AI 不得进入 PTY→像素热路径（§0.4，不可协商）。
