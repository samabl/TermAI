# ADR-0008：许可、商业模式与云边界

> **本 ADR 的许可与商业模式结论已被 [ADR-0013](ADR-0013-license-open-source-scope.md)（AR-21）取代，状态为 Superseded。**
> 取代范围：决策 1（单一许可证）与决策 2（云端闭源专有）。**决策 5–10 的云边界、遥测与供应链结论仍然有效**（AR-11 / AR-12 未变）。
> 其余正文作为历史记录保留，不得删除或改写；后续以 ADR-0013 与 AR-21 为准。

- 状态：Superseded by ADR-0013
- 日期：2025-01-01
- 决策者：Orchestrator（综合 10 角色评审）
- 关联：AR-10、AR-11、AR-12；DC-34、DC-36；HARNESS §0.4、§6.1、§6.3、§8.1、§11（OQ-01）

## 背景与问题
1. 许可分歧：01/03/05/07/09/10 → Apache-2.0；02 → 内核 Apache + 编排 AGPL；06 → 本地 Apache + 云端 BSL 1.1；04/08 → MIT/Apache 双许可。
2. 云边界分歧：06 主张「控制面-only、服务端 prompt 字段 = 0」；07 主张云端评测与跨用户缓存需要数据。
3. 增长侧诉求：遥测默认开启才能做 A/B 与留存分析。
4. 硬红线：PTY 流、文件内容、命令输出、密钥材料永不进入服务端；核心链接边界不得出现 GPL/AGPL（§0.4）。
5. 风险：许可摇摆（R12）与云边界被功能需求侵蚀（R11）都是已被识别的 Top 风险。

## 可选方案（至少 2 个，含被否决项）
| 方案 | 主张方 | 否决 / 采纳理由 |
| --- | --- | --- |
| A 内核 Apache + 编排 AGPL / 或 MIT+Apache 双许可 | 02、04、08 | 否决。AGPL 进入核心链接边界违反 §0.4；双许可并存造成歧义（AR-10 明文禁止） |
| B 本地 Apache + 云端 BSL 1.1 | 06 | 否决。BSL/SSPL 的信任摩擦与企业法务成本高于收益（AR-10） |
| C 核心/SDK/协议 Apache-2.0 + 云服务闭源专有 + 开放协议 | Orchestrator | **采纳**（AR-10） |

## 决策
1. **许可**：核心、SDK、协议 = **Apache-2.0**（含专利授权）；最终单一许可证由法务在 MIT/Apache 二选一确认（OQ-01，P0），**禁止双许可并存**。**明确拒绝 AGPL/GPL 进入核心链接边界**（CI：链接边界 GPL/AGPL = 0）。
2. **商业模式**：云端商业服务（同步、团队、企业策略、托管 AI、私有 registry）= **闭源专有**；改用「闭源服务 + 开放协议 + 开放客户端」，**不采用 BSL/SSPL**。
3. **插件市场 v1 零抽成、无 DRM**；收入来自企业私有 registry、Verified 认证与合规能力。抽成政策变更需 TSC 决议 + 90 天公示。
4. **主题格式与主题商店永久免费开放**（DC-12 主题为纯数据，禁止脚本/CSS 注入）。
5. **云边界硬底线**（AR-11）：PTY 流、文件内容、命令输出、密钥材料**永不进入服务端**；客户端启动不得有阻塞式云调用；**服务端不落 prompt/completion（CI 静态强制字段数 = 0）**。
6. **AI 网关默认只路由与计量**，BYO-Key 直连；仅托管额度通道经我方转发并 UI 明示。
7. **评测真值**仅来自 (a) 用户显式同意并脱敏的会话捐赠（opt-in、可撤回）与 (b) 合成任务集；**不做跨用户 prompt 缓存**；同用户缓存须显式开启（OQ-10）。
8. **遥测默认关闭（opt-in）**，崩溃上报独立开关，**内容零采集**（无命令文本、路径、代码、域名），仅本地聚合计数 + 采样，客户端侧脱敏后才允许上报；所有出站请求可分类、可审计、可在 UI 回看（AR-12）。
9. 同步仅覆盖 CRDT 小文档（设置/片段/工作区元数据）；历史默认仅本地，跨端备份可选且端到端加密；协作优先 P2P/WebRTC + 中继（OQ-16）。
10. 模型视为供应链：权重哈希 + 分发通道签名 + 离线校验（DC-36）。

## 理由
1. Apache-2.0 + 闭源云是「开放客户端 + 开放协议」的可持续组合：企业法务无传染性顾虑，同时保留服务端变现。
2. 零抽成 + 免费主题换取生态规模与信任，收入放到企业合规能力上，与 AR-10 的结论一致。
3. 「服务端 prompt 字段 = 0」是可被 CI 静态强制的硬边界，比任何隐私声明都更可验证（§8.2 隐私验收）。

## 后果（正面 / 负面 / 需要接受的代价）
- 正面：许可清晰、无传染性；隐私可验证；插件与主题生态门槛最低。
- 负面：放弃公共市场抽成的直接收入（06 反方）；编排层缺少传染性保护（02 反方）；遥测稀疏使产品决策数据系统性弱化（PM 反方）。
- 需要接受的代价：
  1. 产品决策只能靠 12 人常驻 dogfood + 每版本 8 人可用性测试 + 社区调研部分补偿（AR-12 明文接受）。
  2. 企业私有 registry、Verified 认证必须真的能变现，否则商业模式承压。
  3. 必须长期维护 CI 静态检查（链接边界许可、prompt 字段数、出站连接分类）。

## 反方记录与复议条件
- **反方（06，保留原文）**：放弃公共市场抽成损失直接收入；BSL 能更好保护云服务投入。
- **反方（02，保留原文）**：编排层缺少传染性保护，竞争对手可白嫖后闭源。
- **反方（增长/PM，保留原文）**：遥测 opt-in 使 A/B 与留存分析系统性弱化。
- **复议触发条件**：
  1. 抽成：商业数据显示公共市场抽成为主要收入来源（**>30%**）时重议，且**不得追溯已发布插件**。
  2. 许可：核心许可 12 个月内变更需 TSC 2/3 + 90 天公示（章程，R12）。
  3. 云边界与遥测默认值**不设复议通道**：属 §6.1 红线与 §10 Anti-features。
