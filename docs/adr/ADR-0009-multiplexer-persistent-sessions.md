# ADR-0009：多路复用与持久会话模型

- 状态：Accepted
- 日期：2025-01-01
- 决策者：Orchestrator（综合 10 角色评审）
- 关联：AR-13；DC-03、DC-04、DC-18、DC-19、DC-20；HARNESS §7（P0/P1）、§8.2、§11（OQ-04/OQ-05）

## 背景与问题
1. 路线选择：把 tmux 作为会话持久化的事实标准并包装它，还是自研会话守护进程替代它？
2. 需求差异：AI-native 要求会话状态**结构化**（命令边界、退出码、cwd、时间戳可被读取）；tmux 的 control-mode 只提供屏幕与控制消息，语义层不在其契约内。
3. 可靠性目标：sessiond 7×24 无泄漏（RSS 漂移 <5%）；UI 崩溃 <2s 重连且屏幕一致；crash-free session >99.9%（§8.2）。
4. 用户现实：大量用户已深度依赖 tmux 键位、配置文件与 .tmux.conf 生态，强制替代会造成迁移摩擦与卸载。
5. 长期含糊点：用户常把「会话恢复」误认为「进程恢复」，这是信任风险（A1）。

## 可选方案（至少 2 个，含被否决项）
| 方案 | 主张方 | 否决 / 采纳理由 |
| --- | --- | --- |
| A 包装 tmux 作为持久化内核 | 复用派 | 否决。无法提供结构化上下文真源；跨平台（Windows/ConPTY）不可用；协议与版本受制于上游 |
| B 自研 sessiond 并**强制替代** tmux | 理想派 | 否决。破坏既有工作流与配置生态，迁移成本高且无用户收益 |
| C 自研 sessiond 为唯一真源 + tmux 键位/control-mode 兼容共存 | Orchestrator | **采纳**（AR-13） |

## 决策
1. **自研 sessiond 为会话唯一真源**：跨平台、结构化上下文、可多端 attach（DC-18）。
2. **tmux 以「键位兼容 + control-mode 兼容客户端」共存，不强制替代**；用户可在 sessiond 内运行 tmux（嵌套场景纳入兼容矩阵，见 R4）。
3. 进程模型：**每用户单守护 + 每会话子任务**（OQ-05 建议，P1 决策）。
4. **UI 崩溃不影响进程**：终端进程继续运行；UI 重启后 <2s 重连且屏幕一致。
5. **重启可重建最后 checkpoint + 尾部段**（Session Log 的 append-only 结构保证可恢复）。
6. **诚实声明（必须在文档与 UI 明示）**：**屏幕可恢复，进程不可恢复**。
7. **恢复语义只还原 cwd/env/布局/滚动/历史，绝不自动重放命令或重启进程**（DC-04）。
8. 传输抽象：Transport = Local | SSH | Container | WSL；原生 SSH（russh），容器/WSL 统一抽象，**不 shell out 系统 ssh**（DC-19）。
9. 持久化默认值：结构化会话元数据（命令边界、退出码、cwd、时间戳、报错摘要）**默认持久**；**完整原始输出 scrollback 持久默认关闭**，可选开启（可加密）（OQ-04 建议）。
10. 滚动缓冲实现：line-arena + style-run，默认 10k 行 / 10MB 上限，冷行下沉磁盘（DC-20）。

## 理由
1. 会话真源必须与结构化上下文同源，否则 AI 读到的是屏幕文本而不是状态（违背 A3）。
2. 兼容而非替代把迁移成本降到零，同时不牺牲自研带来的跨平台与结构化优势。
3. 「屏幕可恢复、进程不可恢复」的明示是信任资产：它防止用户对持久化能力产生错误预期（A1）。

## 后果（正面 / 负面 / 需要接受的代价）
- 正面：结构化会话与多端 attach；Windows/ConPTY 原生支持；UI 崩溃零损失；AI 上下文与真源一致。
- 负面：自研守护进程带来生命周期、升级与状态迁移的长期维护负担；「进程不可恢复」会让部分用户失望。
- 需要接受的代价：
  1. 必须维护 tmux 兼容矩阵（键位、control-mode client、嵌套 tmux）与差异登记。
  2. sessiond 的 7×24 长跑门禁（RSS 漂移 <5%）进入 CI 与发版流程。
  3. 默认不持久化完整原始输出，需要恢复完整历史的用户必须显式开启并接受存储/加密成本。

## 反方记录与复议条件
- **反方（复用派 / 04 内部少数意见）**：tmux 已被验证十余年，自研守护进程重复造轮子，bug 面积与迁移风险高。
- **反方（理想派）**：不强制替代会长期背负两套多路复用语义，文档与支持成本翻倍。
- **复议触发条件**：
  1. 若 sessiond 的 7×24 RSS 漂移 ≥5% 或 UI 重连 >2s 连续两个版本不达标（R7 类性能侵蚀），则降级为「sessiond held，tmux 作为可选后端」的过渡方案。
  2. 若兼容层导致 tmux 用户在 P0–P1 阶段出现阻塞性缺陷，优先修兼容而非推进替代。
- 不可放宽：屏幕/进程恢复语义的诚实声明不得删除或模糊化；绝不自动重放命令（DC-04）。
