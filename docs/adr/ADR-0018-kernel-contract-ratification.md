# ADR-0018：内核对外契约变更追认（PtyBackend 九元面 / IPC CBOR+POD / crc32c 强制）

- 状态：Accepted
- 日期：2025-01-01
- 决策者：Orchestrator（综合 P0 内核七份评审）
- 关联：AR-28 第 1 条（接口面扩张按对外契约变更处理）、AR-25（字节保真与车道）、AR-04 与 DC-22（通信层）、DC-40（兼容窗口）、ADR-0014（平台与参考机）、ADR-0015（依赖许可白名单）
- 影响实现：kernel/02（PTY 与平台层）、kernel/07（内核 API/ABI）、docs/spec/03-system-architecture.md 的 §3.4 与 §3.6

## 背景与问题

P0 内核评审在落地过程中产生三处**对外契约变更**，均超出原规格的授权范围。按 AR-28 第 1 条，这类变更必须补 ADR 追认并走 CODEOWNERS 双签，否则不得冻结接口。

## 决策

### D1 PtyBackend 由 6 元面扩为 9 元面

- **新增元面**：signal、process_tree（含 tree_snapshot）、capabilities；原有 spawn / write / read / resize / kill / wait 保持不变。
- **理由**：Windows 无 POSIX 信号、进程树需要 Job Object 语义、平台能力必须可查询（否则调用方会写出「假设 POSIX」的分支）。三者都是跨平台正确性的必要条件，不是可选便利接口。
- **代价**：契约面扩大 → 实现与测试成本上升；capabilities 会诱使调用方写平台分支（需以「能力查询 + 统一降级」约束）。

### D2 IPC payload 编码 = CBOR + POD 双档

- **POD 档**：固定布局、上限 4 KiB，用于所有**热路径**消息（输入、GridDelta、resize、生命周期事件）。
- **CBOR 档**：自描述、可扩展，用于低频与演进型消息（已知 tag 之外的扩展、审计与握手元数据）。
- **理由**：全栈只维护**一种**二进制自描述编码（与 capability 令牌编码同源），避免 Cap'n Proto 与 MessagePack 双栈并存；热路径的确定性由 POD 档保证。
- **代价**：CBOR 不得出现在热路径，因此新增热路径消息必须显式选择 POD 档并固定布局（增加设计摩擦）。

### D3 crc32c 由「可选」升级为「强制」

- **适用范围**：IPC 帧头校验 + 共享内存槽校验，两者**同语义**。
- **理由**：IPC 是 §8.1-6 的 fuzz 靶面；若共享内存与 IPC 使用不同校验语义，会留下「一处校验通过、另一处静默损坏」的缺口。
- **代价**：每帧 4 字节开销与计算成本（可用硬件指令摊薄）。

## 后果

**正面**：接口面与平台能力一次性说清；编码从「留给 ADR」变为已决；IPC 与 shm 校验语义统一，损坏可检测。

**负面**：三项变更都需回填 spec 03 与 kernel/07；POD 档 4 KiB 上限会约束未来的大消息设计（大快照走独立共享内存路径，不挤进单帧）。

## 反方记录与复议条件

- **反方（对 D2）**：统一用 CBOR 更省事、更少分支。**否决**：CBOR 解析不确定，进不了热路径；而热路径既然已用 POD，「统一一种编码」的收益已经拿到。
- **反方（对 D3）**：校验成本可能吃掉 IPC 预算（kernel/07 新增指标 N-2 附加延迟 P99 不超过 20 微秒）。**复议条件**：若实测显示校验使 N-2 超预算，可退化为**按帧类型分级**（热路径轻校验 + 控制帧强校验），但**共享内存槽校验不得降级**。
- **通用复议条件**：本 ADR 三项决策的变更需 TSC 2/3 加 90 天公示（AGENTS.md §5），且不得与 AR-25 的字节保真契约冲突。

- 回填清单：docs/spec/03-system-architecture.md 的 §3.6（6 元面 → 9 元面 + 指向本 ADR）与 §3.4（编码裁定 + crc32c 强制）。
