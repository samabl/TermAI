# ADR-0005：风险分级、审批与撤销模型

- 状态：Accepted
- 日期：2025-01-01
- 决策者：Orchestrator（综合 10 角色评审）
- 关联：AR-06；DC-11、DC-32、DC-34、DC-35；HARNESS §1.4、§6.1、§6.2、§8.2、§11（OQ-08/OQ-20）

## 背景与问题
1. 三方分歧：08 主张「危险动作逐条批准，且不可配置关闭」；02 主张「拒绝逐条确认（盲确认率反升），改分级摩擦 + 二次输入目标名」；07 主张「四级 + 三档授权，信任模式最多放行 L0/L1」。
2. 量化目标：危险命令误执行率 <0.5%，L2/L3 未审批执行 = 0，盲确认率 <15%（§1.4、§8.2）。
3. 关键洞察：确认疲劳会让安全性**低于**「无确认 + 可撤销」；但不可逆操作没有事后补偿路径，因此必须区分可逆与不可逆。
4. 撤销栈的能力边界长期被含糊：暗示可回滚 OS/容器/远端会造成信任崩塌（A1：终端是信任基础设施）。

## 可选方案（至少 2 个，含被否决项）
| 方案 | 主张方 | 否决 / 采纳理由 |
| --- | --- | --- |
| A 逐条弹窗式确认 | 08 | 否决。盲确认率反升，与 §8.2「盲确认率 <15%」冲突；也列为 Anti-features §10.13 |
| B 零确认自动执行（信任模式放行一切） | — | 否决。违反 §6.1 红线 1 与 §10.3，L2/L3 未审批执行必须为 0 |
| C 分级摩擦 + 二次输入目标名 + 三档授权 | 02 + 07 + 08 的收敛 | **采纳**（AR-06） |

## 决策
1. **风险分级**：L0 只读 / L1 幂等写 / L2 破坏性 / L3 不可逆或外发 / **U 不可判定（按 L2 起步并说明原因）**。
2. **授权三档**：once / session / rule；**L0、L1** 可被规则固化；**L2 必须每次 dry-run + 确认**；**L3 必须每次确认 + 二次输入目标名/短语 + 不可回滚徽章**。
3. **不可协商**：破坏性与外发型操作的确认**不可由配置关闭**；企业策略**只能加强，不能削弱**（§0.4 第 3 条、DC-35 capability-based 默认拒绝）。
4. 采纳 02 的交互形态（分级摩擦 + 二次输入），同时否决「逐条弹窗」与「零确认自动执行」两个极端。
5. **撤销栈只承诺工作区文件与 git 可逆操作**；绝不承诺 OS/容器/远端回滚；UI 必须明示边界（OQ-20）。
6. 七条命令黄金规则强制且不可关闭（DC-32）：能力与意图分离、禁止 shell -c 拼接、默认 dry-run、危险动作逐条批准、污点追踪、最小权限执行、可回滚。
7. 审计 append-only + 本地哈希链，记录操作者（人/插件/模型）、审批人、结果（DC-34）；UI 侧呈现四级风险色阶（DC-11）。

## 理由
1. 用户在**认知负荷**与**不可逆代价**之间做权衡，是最优的安全经济学：摩擦只施加在真正需要它的等级上。
2. 二次输入目标名把「手指肌肉记忆」转化为显式语义确认，直接压制盲确认（§8.2 盲确认率 <15%）。
3. U 级按 L2 起步，杜绝「分类器不确定 → 放行」这一最危险的失败模式。
4. 明确的撤销边界是信任资产：承诺少但从不食言，优于承诺多而事后解释。

## 后果（正面 / 负面 / 需要接受的代价）
- 正面：误执行率与盲确认率可同时达标；审计可导出 SIEM（P4）；企业策略有加强空间。
- 负面：L2/L3 交互步骤增多，自动化率（NSM Accepted AI Actions per WAU ≥5）承压；U 级误分类会带来额外摩擦。
- 需要接受的代价：
  1. 必须实现风险分类器 + shell AST 预分析，**解析失败按更高风险保守处理**（DC-27）。
  2. 撤销栈需前置写快照，带来磁盘与延迟成本；不覆盖容器/远端必须写进 UI 文案。
  3. 「信任模式」在 v1 中默认关闭，最多放行 L0/L1 且记录审计（OQ-08，Phase P2 决策）。

## 反方记录与复议条件
- **反方（08，保留原文）**：逐条批准才是最可靠的安全姿态；分级摩擦给了「以为安全」的错觉，且规则固化可能被滥用。
- **反方（02，保留原文）**：逐条确认会让盲确认率反升，安全性反而下降；主张即便 L3 也应优化交互形态而非堆叠弹窗。
- **复议触发条件**：
  1. 若实测盲确认率 ≥15%，则提高 L2 摩擦档位（例如 L2 也引入二次输入短词）。
  2. 若 L2/L3 未审批执行出现任何一次，立即冻结相关规则固化路径并触发事故复盘。
  3. 若撤销栈扩展覆盖容器/远端（OQ-20 建议为「不覆盖」），必须新开 ADR 并给出可验证的回滚证据。
- 不可放宽：确认不可由配置关闭；企业策略不得削弱默认值。
