## 1. 目的与范围

### 1.1 目的

TermAI 的体验层与内核同级可验收：所有审美争论必须落成**数值 + CI 门禁**（对比度、对齐误差、动效时长、间距/圆角/图标标尺、像素 diff、键盘覆盖率）。本规格定义**信息架构与布局（终端唯一主体、单一左侧栏、设置独立窗口、新建终端选择器、窗口控制跟随平台）**、交互与快捷键、AI 入口、Agent Scope、信任交互、错误体验、渐进披露、token v2 与视觉语言、信息密度、小 UI 去文字、终端软换行、滚动条策略、画质、a11y 与 i18n。

### 1.2 范围内

| 域 | 交付物 | 主责层 |
| --- | --- | --- |
| 信息架构与布局（AR-23 / ADR-0017） | 终端唯一主体；单一左侧栏（48px rail + 内容面板、7 分区、底部 Settings 与收起）；Workspace > Tab > Pane(≤8) 树；三「会话」命名契约；恢复语义；设置独立浮动窗口与跨窗口联动；窗口控制跟随平台（mac / win 两形态、三态真实）；新建终端选择器（tab「+」） | L1 + L2 + ui-native + shell-bridge |

## 3. 详细设计

### 3.1 信息架构与命名契约（AR-23 / ADR-0017 修订）

**树与持久化**：Workspace（持久化单元）> Tab（任务/主机）> Pane（分屏树，上限 8）；节点为 Leaf(paneId) | Split(dir, ratio, a, b)，同向插入折叠、稳定 ID、支持拖拽 reparent；布局 + 启动命令存为模板；重建不自动执行模板命令（C4）。**布局落点（AR-23 / ADR-0017）**：树结构不变，但 **Workspace 不再拥有整屏视图**，Workspace / Hosts / Credentials / Known Hosts 的浏览与管理全部落在单一左侧栏的 Workspaces 分区内（§3.2），主区任何时刻只有终端；DC-03 的三「会话」命名契约不受布局重构影响。

| 概念 | 唯一 English 名 | 中文 UI 文案 | 禁止用法 |
| --- | --- | --- | --- |
| 进程与缓冲 | PTY Session | 终端会话 | 单独用「会话」指代、与恢复语义混用 |
| 模型上下文与工具权限 | Agent Session | AI 会话 | 「助手会话」「对话会话」 |
| 磁盘持久化单元 | Workspace | 工作区 | 「会话」「项目会话」 |

**恢复文案契约（C4）**：允许「恢复布局 / 恢复工作目录 / 恢复滚动历史 / 重新连接屏幕」；禁止「恢复进程」「重启会话」「恢复运行中的任务」。恢复面板必须同行显示固定诚实声明，措辞可 i18n 但语义不可软化。**多端 attach（AR-13）**：同一 PTY Session 可被多端 attach，UI 必须显示 attach 端数与「谁可写 stdin」，输入焦点归属唯一，非焦点端只读并标注。

### 3.2 终端唯一主体与单一左侧栏（AR-23 第 1–2 条 / ADR-0017 D1–D2）

**主区契约**：主区 = tab 条 + 终端网格 + 状态栏；任何时刻**有且只有一个 view = 终端**。**不存在「终端 / 工作区」视图切换**，不存在整屏的工作区 / 主机 / 设置页面；侧栏展开或收起都不改变主区归属。非终端内容一律进入侧栏面板（本节）或独立窗口（§3.3），**永不整屏抢占终端**。

**侧栏结构**：48px 图标轨道 **rail** + 内容 **panel**；分区**固定七项**——① Workspaces（分组卡片 / 列表 + **内嵌资源视图 Hosts / Credentials / Known Hosts** + 第二条「新建终端」入口；面板内必备搜索、分组与键盘导航；不占主区）｜② Sessions（PTY Session 列表、attach 端数与「谁可写 stdin」，AR-13）｜③ **Agent**（AI 对话全部内容：输出原语、作用域指示器、审批卡；**按需展开**，§3.6）｜④ Snippets｜⑤ Themes（主题 = 纯数据，C19）｜⑥ Plugins（v1 仅 Tier1，AR-08）｜⑦ Audit Log（只读，可导出 SIEM）——**底部固定 Settings（§3.3）与「收起侧栏」**，两项常驻、不随分区内容滚动。侧栏**固定在左侧**（「左 / 右」仅作设置项，默认左，供 RTL 与个人偏好）；整体可收起（**Mod+B**），**收起后保留 48px rail**（rail 恒显，让用户「一眼看出怎么展开」）。

**rail 与键盘（AR-23 / ADR-0017）**：rail 只放图标（内联 SVG、stroke 1.5、仅 16/20/24 三档），每项 title + tooltip（400ms、focus 亦显示、Esc 关闭）+ aria-label、**无可见文字**——这修订了 AR-22 第 3 条「主导航保留可见文字」的落点，可发现性由 tooltip + Mod+K（macOS `⌘K` / Win·Linux `Ctrl+Shift+K`）+ panel 内保留可见文字的分区标题承担（§3.12）。rail 与 panel 同一焦点环内可达，**7 个分区每个都能纯键盘到达并操作**（Tab 进 rail → 方向键选分区 → Tab 进 panel 首项），**收起态下 rail 仍全部可达**，当前分区以 accent + aria-current 指示。**代价与缓解**：工作区 / 主机浏览失去全屏舞台，检索效率必须在面板内重建（搜索、分组、批量选择、键盘导航）；Agent 由「常驻可见」变「按需展开」，代价与补偿见 §3.6。**复议条件**：AI 使用率或跨会话操作数相对 v3 基线下降 >30% 时，回退「Agent 常驻右栏」或提供「Agent 常驻」开关（§7 UX-OQ-18）。

### 3.3 设置独立窗口、跨窗口联动与窗口控制（AR-23 第 3、5 条 / ADR-0017 D3、D5）

**设置独立窗口**：Settings **不占主区**，作为**独立浮动窗口**打开——自有标题栏、自有窗口控制，圆角与投影沿用设计系统（§3.11）；内容含主题（深 / 浅 / 跟随系统 / 高对比）、字号与字体、**软换行开关**、侧栏位置（左 / 右）、**窗口控制位置**、快捷键表。主题、字号、软换行由 Core 持有**单一权威状态**并**跨窗口实时双向联动**（任一窗口改动，另一窗口 ≤1 帧内反映，不重启、不刷新）；窗口可关闭，关闭后从**侧栏底部 Settings** 重开且不丢设置（写配置体系 AR-09，不依赖窗口存活）；**非模态**，不阻断终端输入（延续 C2），Esc 关闭并把焦点交还触发元素。

**窗口控制：真实可用，位置与形态跟随平台**：**macOS = 左上角圆点**（红 / 黄 / 绿，hover 显出 × / − / ⤢，位置、顺序与反馈符合平台惯例）；**Windows / Linux = 右上角扁平图标按钮**（最小化 / 最大化 / 关闭，顺序与分组符合平台惯例、不得与顶栏「更多」混淆）。每个按钮替换掉任何仅作装饰、aria-hidden 的圆点，**可聚焦、可键盘操作**、带 aria-label 与 tooltip（C13）；三态行为真实——**最大化 / 全屏** = 铺满视口（去掉壁纸留白与外距）再点还原，**最小化** = 收成可点击胶囊 / 缩略条并点击还原，**关闭** = 关闭该窗口且主窗口在壁纸保留「重新打开 TermAI」入口（**不得进入死态**），设置窗口同样适用。**统一范围（方案 A）**：仅位置与按钮形态随平台，**圆角 / 投影 / 配色仍统一**——避免维护第二套窗口 chrome，也不给 AR-22 的统一标尺开平台例外；**否决方案 B**（窗口外观也完全按平台渲染），**复议条件**：Windows dogfood 出现明显「半原生」违和感或误触时再评估方案 B，或退化为「全平台统一 macOS 式左上」。设置项「窗口控制位置」默认**跟随平台**，可强制 macOS 式 / Windows 式；评审可用原型 hash 直达两种形态（ADR-0017 D5）。

### 3.4 新建终端 = 新增标签页时选择（AR-23 第 4 条 / ADR-0017 D4）

**唯一主入口 = tab 条「+」**：打开「新建终端」选择器，可选本地 Shell（zsh / bash / fish / pwsh）、SSH 主机（最近 / 收藏）、容器（docker exec / kubectl exec）、WSL、已保存会话、从模板；**顶栏不再有「连接主机 / 新建工作区」**，二者不得以任何其它可见入口回到主区（A31）。**交互与落点**：**搜索 + ↑↓ + Enter + Esc** 全键盘可用；选定后**真实新增并激活一个 tab**，Esc 取消**不产生副作用**；选择器是 tab 条上的**浮层**（chrome，属 shell-bridge），不是新页面、不占主区，每个条目注册稳定 action id 进 Action Registry 可被 Mod+K 命令面板检索（C5）。**第二入口**：侧栏 Workspaces 分区保留「新建终端」，与 tab「+」是**同一 action**；默认排序与默认键位尚未裁决（§7 UX-OQ-21 / ADR-0017 OQ-5）。

### 3.5 交互模型与快捷键体系（不变 + AR-23 键位）

**Mod 的平台展开（AR-29 第 2 条）**：macOS = `Cmd` 系；**Windows / Linux 默认 = `Ctrl+Shift` 系**（把裸 `Ctrl+字母` 尽量留给终端应用）。文档中出现 `Mod` 一律标明平台结果——`Mod+K` = `Cmd+K` / `Ctrl+Shift+K`、`Mod+B` = `Cmd+B` / `Ctrl+Shift+B`（AR-29 明确的两条冻结键位）；其余含 `Mod+Shift` 的组合在 Windows / Linux 会与 `Ctrl+Shift` 前缀相撞，其展开按 Action Registry 的键位分配，**冲突以改绑解决**（未冻结项见 §7 UX-OQ-21）。本规格冻结以下全局键位；其余键位由 action registry 定义并可重映射（AR-09 TOML）。

**平台展开规则（AR-29 第 7 条，对第 2 条的澄清）**：`Mod` 是按平台展开的抽象——macOS = `Cmd`，**Windows / Linux = `Ctrl+Shift` 整体**（不是裸 `Ctrl`）。因此凡在 macOS 上以 `Mod+Shift+X` 形式存在的动作，**不得**机械展开为 `Ctrl+Shift+Shift+X`，必须在 Win/Linux **重新分配**（**优先 `Ctrl+Alt` 系**）；所有动作的三平台展开结果必须在 **Action Registry 中显式登记**（macOS / Windows / Linux 三列），CI 以静态门禁 **S10** 校验展开后**零冲突**。文档中出现的 `Mod` / `⌘` 必须标注平台展开，**不得用 `⌘` 作为全平台代称**。

| 键位 | 动作 | 语义 |
| --- | --- | --- |
| Mod+K | 命令面板 | 全局动作入口，覆盖 100% 功能 |
| Mod+Shift+P | 命令簿 | 全量动作（含无键位动作）的完整清单 |
| Mod+P | 快速打开 | 文件 / 主机 / 容器 |
| Mod+Enter | 把当前输入交给 AI | 输入行内容 → Agent，不直接执行 |
| Mod+I | 展开 / 收起侧栏的 **Agent 分区** | **AR-16 修订版**：原「切换 AI 面板」被重新定义为侧栏 Agent 分区的开关（AR-23） |
| **Mod+B** / Mod+,（建议） | **收起 / 展开侧栏**（收起保留 48px rail） / 打开设置窗口 | **Mod+B = AR-23 第 2 条（冻结键位）**；Mod+, 与 Mod+T（新建终端）为本规格建议，进 Action Registry 待定键位（§7 UX-OQ-21），**不是** HARNESS 冻结项 |
| Mod+反斜杠 / Mod+Shift+反斜杠 | 垂直/水平分屏 | 分屏树操作 |
| Mod+W 关闭 Pane / Mod+1..9 切 Tab | 结构操作 | 关闭 Pane 前若有前台进程须提示 |

**键位冲突优先级**（高 → 低）：L4 平台原生（含窗口控制）> **核心快捷键（在 FocusRouter 层始终优先）** > 网格内应用模式（应用键盘模式 / kitty keyboard protocol 探测，默认不主动开启，见 OQ-06）> 用户/插件绑定。**AR-29 第 1 条**：终端核心快捷键不得让位于应用模式——冲突以**改绑按键**解决（改应用键位或改 TermAI 键位），而不是让出优先级，否则在 Windows / Linux（默认 `Ctrl+Shift` 系）上用户无法可靠呼出命令面板与侧栏、也无法从卡死的应用中逃生。tmux 前缀键（Ctrl-b / Ctrl-a）不得被内核抢占；提供「shell 优先」逃生阀与一键键位重映射导入。

**命令面板 100% 覆盖机制（C5）**：① **Action Registry 是唯一真相源**——每个可点击项、菜单项、快捷键都注册稳定 action id，携带 i18n key、默认键位、面板可见性、风险等级、是否需确认；② **同一契约对外复用（DC-24）**——Local API 与 CLI --json 暴露同一 registry，禁止 UI 另建清单；③ **CI 校验**——菜单/按钮/快捷键的 action id 集合与 registry 差集为空，未注册即阻断合并；④ **治理**——排序与分组白名单人工维护、按近期使用加权，每季度清理最低使用率入口。**侧栏 rail 的 7 个分区、设置窗口、新建终端选择器条目都是注册动作**。**去文字后的兜底（AR-22 / ADR-0016）**：任何被图标化的动作都必须能在 Mod+K 命令面板中以文字检索到，命令面板 100% 覆盖由「可发现性补偿」升级为**硬约束**。

### 3.6 AI 五类入口：触发、场景、失败模式、互斥（AR-16 经 AR-23 修订）

| 入口 | 触发 | 场景 | 主要失败模式 | 互斥与优先级 |
| --- | --- | --- | --- | --- |
| 内联 Agent（行首 ??） | 行首输入 ?? | 老手快速生成命令 | 与 shell 语法冲突；发现性差；污染脚本化 | **第一入口**。与内联 ghost text 互斥（同一行）；结果落输入行由人确认后执行，历史中标记为 AI 生成，不伪装成手输 |
| **侧栏 Agent 分区**（原「侧边面板」，AR-23 / ADR-0017 修订） | Mod+I / 侧栏 rail 的 Agent 图标 / 错误卡「AI 解释」 | 多步任务、解释报错、跨会话调查 | **不再持续可见**导致发现性下降；与其它分区分时复用同一面板宽度 | **主场，按需展开**。位于**左侧栏的 Agent 分区**（不再是右侧常驻栏）；展开占用侧栏面板宽度，**≤40% 视口宽的上限不变**；与全屏 Chat 共用同一槽位，互斥 |
| Ghost text | 输入时 | 命令名、路径、分支、容器名补全 | 幻觉参数被 Tab 误接受 | 仅补全。shell 原生补全优先，无候选时才显示；与整行灰字预测互斥；**建议不得含 L2/L3 操作**（AST 预分析命中即降级为 Inline Hint，不上输入行） |
| 全屏 Chat / 整行灰字预测 | Agent 分区内切换 / 空闲时 | 长教学与方案讨论 / 重复性任务 | 脱离上下文与复制损耗 / 噪音、打断心流、被永久关闭 | 全屏 Chat 仅分区**次级模式**、不设独立入口；整行灰字预测**默认关闭**且与 ghost text 互斥 |

**接受语义**：Tab 接受当前 token 段、End 接受整行；接受前整行可审阅；**任何 AI 生成的候选都不得以 Enter 直接执行**。内联 ?? 的产出必须先进入输入行（可编辑、可复制），保证「复制出的命令在别处跑得通」。**跨会话调查** 受 Agent Scope 约束：P2 起只读跨会话、引用须标注来源会话，不得因此产生写操作（§3.8）。**AR-16 修订后的代价与缓解（AR-23 / ADR-0017）**：AR-16 的原始证据是「AI 若制造第二焦点会被永久关闭」，因此把 Agent 由「右侧常驻」改为「左侧栏按需展开」时必须补偿——① **内联 ?? 承担「随叫随到」的第一入口**（顺序第一位不变），任何 AI 能力都不得出现「只能从侧栏进入」的情形；② **Agent 分区拥有独立快捷键**（Mod+I）与 rail 图标，一键直达且不打断终端输入；③ **首次出现可解释场景时做一次性、可永久关闭的情境提示**（C2 / §3.10 渐进披露）；④ **预留「Agent 常驻」开关**（§7 UX-OQ-18）。**复议条件**：若线上数据显示 AI 使用率或跨会话操作数相对 v3 基线下降 >30%，回退「Agent 常驻右栏」或启用常驻开关。

### 3.7 信任与安全交互（AR-06，不变）

| 等级 | 判定 | 界面表达 | 摩擦 | 可撤销性标注 |
| --- | --- | --- | --- | --- |
| L0 只读 | 无写副作用 | 中性 chip「只读」 | 无 | 不适用 |
| L1 幂等写 | 工作区文件、git 可逆 | chip「可撤销」+ 事后 Undo 提示 | 执行 + 事后提示 | 快照 / git 引用 |
| L2 破坏性 | rm -rf、force push、drop、kubectl delete | 强制 dry-run 面板 + 危险色 + 目标名输入 | **每次** dry-run + 确认 | 「部分可撤销」 |
| L3 不可逆/外发 | 生产集群、云 API、密钥 | 环境色带（生产=红）+ 完整目标名/短语输入 + **不可回滚徽章** | **每次**逐条批准 | 「不可回滚」 |
| U 不可判定 | 脚本、动态拼接、黑盒 | chip「不可判定」+ 判定原因文本 | 按 L2 起步 | 无承诺 |

**dry-run 面板必备五要素**（黄金规则 3，不变）：完整命令（argv 展示，非拼接字符串）、影响面标签（读/写/网络/提权）、目标主机与路径、风险等级与判定依据、数据来源标记（对来自终端输出/文件等不可信来源的值标注来源，见黄金规则 5）。

**不可绕过的约束**：L2/L3 确认不可由配置关闭，企业策略只能加强（C8）；L0/L1 可经 once/session/rule 固化，L2/L3 禁止整类「永远允许」。信任模式最多放行 L0/L1，默认关闭且记审计（OQ-08）。确认对话框在 5 秒内不可完成（二次输入天然满足 L3；L2 同样要求输入目标名），以压制盲确认（目标 <15%）；拦截必须给「为什么被拦」，解释优先于警告。

**撤销栈边界（C8）**：撤销面板列出时间、操作、范围、可撤销性四列；对容器/远端/OS 级操作固定显示「不可撤销」，禁止暗示性措辞。撤销入口同时提供「AI 动作审计」与「出站请求回看」两个视图（C23），满足 100% 出网可在 UI 回看。

**跨会话升级规则（AR-22 / ADR-0016）**：任何跨会话写操作在本表基础上**风险上调一档**（L1→L2、L2→L3），且不得被 once/session/rule 固化；审批卡必须列出全部目标会话并要求二次输入目标名（§3.8）。

### 3.8 Agent Scope 模型（AR-22 / ADR-0016，细化 DC-03）

Agent Session 与 PTY Session 的关系由「两个平行会话」明确为「**可提升作用域的上下文对象**」。

| 作用域 | 含义 | 允许操作 | 写操作风险 | 阶段 |
| --- | --- | --- | --- | --- |
| **本会话**（默认） | 绑定当前激活的 PTY Session，随 tab/pane 切换跟随 | 读写当前会话上下文 | 按 AR-06 常规分级 | P2 |
| **本工作区**（只读跨会话） | 只读引用同 Workspace 其他会话的结构化上下文（命令块/exit code/cwd/错误摘要） | **只读**，引用须标注来源会话 | 不适用（禁写） | **P2 只交付到此** |
| **多选会话** | 用户显式勾选参与会话（同 Workspace 内） | 读 + 写（逐次审批） | **风险上调一档**（L1→L2、L2→L3） | **P3 起**（需能力令牌与审计链先落地） |

**硬约束**：① **P2 只交付「本会话 + 只读跨会话」**，跨会话写延迟到 P3，P2 不得以任何开关提前开放；② 跨会话引用默认**只读**，跨会话写**不得**被 session/rule 白名单固化；③ 审批卡必须**列出全部目标会话**并**二次输入目标名**，目标集合为空或解析失败即拒绝；④ 审计记录「操作者=Agent、作用域、目标会话集合、审批人、结果」（DC-34）；⑤ 作用域只能由用户显式提升/降级，Agent 不得自行提升，也不得借跨会话引用扩大可达范围。

**作用域指示器**：常驻于**侧栏 Agent 分区头部**（AI 关闭时 Agent 分区仍在，指示器仍可见），显示作用域名 + 参与会话数；非「本会话」时用 accent 强调并展开参与会话清单（tab/pane 标题 + 主机）。**跨会话引用**以来源会话 chip 标注（如「来自 tab 2 · prod-web-01」），chip 可跳转、只读、不是写入口；指示器是「Agent 代表哪个上下文行动」的唯一长期可见证据。

**跟随与钉死（防越权）**：作用域=本会话时切 tab/pane 即跟随，但**已发出的审批请求钉死其作用域快照**——审批期间切换会话则请求作废或明确提示重绑，禁止「审批的是 A 会话，执行到 B 会话」。任何不确定（多端 attach 争用、会话消失、权限不足、WebView 重连）**默认降级**为本会话或只读，**不得默认提升**（AGENTS.md §7.4 保守默认）。

### 3.9 错误体验（C6，不变）

Error Artifact = { pane_id, command_argv, exit_code, signal?, stderr_raw, stdout_tail, cwd, started_at, duration_ms, risk_tier }，由 OSC 133/633 结构化产生。

| 呈现位置 | 规则 |
| --- | --- |
| 命令块头 | 原始 exit code 数字；被信号终止显示 signal 名与编号（如 137 / SIGKILL）；**不翻译为「失败了」等美化措辞** |
| stderr | 默认原样呈现并保留原始顺序与 ANSI；折叠阈值 >200 行，折叠后仍可「展开全部 / 复制全部」，且折叠不影响 AI 上下文完整性 |
| 退出码 0 但 stderr 非空 | 必须显示 stderr，并标注「无错误退出码，但有 stderr 输出」 |
| 下一步动作 | 「AI 解释」「带上下文提问」「复制为 issue」「复制原始输出」「手动重跑（不自动）」 |
| 连接类失败 | 三类分离：网络不可达 / 认证失败 / 远端命令失败，各给不同下一步与检查项 |

**禁止项**：吞 stderr、隐去非零退出码、把 stderr 合并进 stdout 美化、自动重放失败命令（C4）。

### 3.10 渐进披露四级（C2，不变）

| 级 | 内容 | 触发条件 | 退出 |
| --- | --- | --- | --- |
| L0 零配置 | 即普通终端，首屏即输入、零弹窗 | 始终 | — |
| L1 命令面板 | 可发现性主入口；任何能力都能变成可复制文本 | 用户首次按 Mod+K | 可关闭提示 |
| L2 内联 ?? 与 Agent 分区 | AI 能力发现 | **仅**首次报错、首次危险命令、或用户显式触发 | 每个提示可永久关闭，关闭后不复发 |
| L3 模板与插件 API | 工作区模板、插件、headless/CLI | 用户主动进入设置或插件页 | — |

反模式（禁止）：欢迎向导、开机导览、课程式步骤、强制登录后才可用。AI 关闭时 L0/L1 完整可用，列为回归项（§5）。**Agent 分区/新建终端选择器等新入口不得被用来做「功能导览」**：新入口的可发现性由 rail tooltip、Mod+K 命令面板与一次性情境提示承担（§3.2 / §3.6），去文字（AR-22）不得被当作「命令面板是唯一发现途径」的借口：图标仍须有 tooltip。

### 3.11 视觉语言 v2 与 Design Token 七组（AR-22 / ADR-0016）

**视觉语言**：macOS 风格浮动圆角窗 + 卡片化；**azure 蓝为唯一主色**，仅用于主操作/选中/焦点/链接；彩色仅用于对象身份色块（工作区、主机图标），其余中性灰阶；**emoji 只允许出现在 AI 回答正文，不得用作 chrome 图标**；按钮只允许 primary（实心 accent）/ secondary（描边幽灵）/ tertiary（纯图标）/ danger（实心红）四级。

**主题取值（AR-22 / ADR-0016 固定，tokens 不得偏离）**：深色一等主题——画布 #08090C、卡片 #17191F、浮起 #1E2129、边框 #2A2F38、正文 #E7E9EE、次要 #9BA3B0；浅色**同等的一等主题**——画布 #F6F5F2（暖米白）、卡片 #FFFFFF、边框 #E6E4DF、正文 #1B1D21、次要 #616874；accent 深 #4A9EFF / 浅 #245BC9。深/浅切换由 §3.16 的默认主题（跟随系统）驱动。

| 组 | v2 取值与规格 |
| --- | --- |
| palette | 三层：primitive（灰阶 12 级 + 8 色相 × 6 级，含 azure 色阶）→ semantic → component；语义层至少覆盖上述七个键；含 terminal.ansi.{0..15} 与选区/光标语义 |
| type | JetBrains Mono / Nerd Font Symbols / CJK 系统回退栈；字号为**两条阶梯**（唯一真相源：`tokens/base/type.json` 的 `ladder` 字段）——**UI 阶梯 12 / 13 / 14（正文默认）/ 15（区块标题）/ 16 / 18 / 20**；**终端阶梯 12 / 12.5 / 14 / 16 / 18 / 20（终端字号独立可调）**；**UI 行高 1.5–1.6、终端网格行高 1.25** |
| space | **单一标尺 4 / 8 / 12 / 16 / 24 / 32 / 48，禁止任意值**（静态检查 A23） |
| radius | 输入 **8** / 卡片 **10** / 弹层 **14** / chip·头像 **999**；终端画布圆角 = 0（网格不得圆角化） |
| elevation | 0–3；深色用「亮边 + 低透明阴影」而非纯黑投影；浅色用弱阴影 + 边框 |
| motion | 120/180/240ms + ease；ease-standard=(0.2,0,0,1)，ease-out-quart 用于进入；reduced-motion 即时退化 |

**图标**：统一**内联 SVG、stroke 1.5、仅 16 / 20 / 24 三档**，不得出现第四档尺寸或 emoji 图标；**侧栏 rail 图标与窗口控制图标都取自这同一套**（AR-23 / ADR-0017：只让位置与形态随平台，图标语言不随平台分叉）；来源与许可见 §7 UX-OQ-14（须过 ADR-0015 白名单）。**唯一真相源与管线（不变）**：token 仍是唯一视觉真源；语义命名（bg.canvas / fg.muted / ai.risk.*）；组件只允许引用 semantic 与 component 层，禁止直引 primitive；仓库硬编码色值 = 0（CI 阻断）。**codegen 管线（DC-09）不变**：tokens/*.json → JSON Schema 校验 → tokens.css / tokens.ts / tokens.rs / theme.schema.json / 文档站 → 产物入库 → CI 幂等校验（重生成零 diff）。

### 3.12 视觉语言 v2 落地细则：密度、去文字、软换行、滚动条、布局容积（AR-22 / ADR-0016 / AR-23）

**信息密度与留白**：卡片 padding ≥16（**推荐 20**）、卡片间距 ≥16、区块间距 ≥32；UI 行高 1.5–1.6；**终端网格行高 1.25（不变，AR-14），密度标尺不适用于网格**；状态栏高度 ≥28px；顶栏次要动作收进「更多」菜单（AR-23 后顶栏只剩面包屑、搜索、侧栏开关与「更多」）。**代价与复议（ADR-0016 反方记录）**：终端纯粹主义反方认为宽松留白浪费屏幕；**保留意见**——若 dogfood 显示「同等任务平均耗时或会话数下降」则回购密度，但只能**提供「紧凑模式」**（标尺内取小值），**不得整体回退视觉语言**（§7 UX-OQ-16），且密度永远不得突破 4 的标尺。

**小 UI 去文字与 tooltip**：**必须图标化（禁止可见文字）**——顶栏、卡片操作、状态栏、面板头部、终端状态条上的次要按钮，**以及侧栏 rail 的分区图标与窗口控制按钮**；**保留可见文字**——侧栏面板的分区标题、主按钮（primary）、分段控件，且不可逆/外发操作的确认按钮必须带文字（防误击）。**每个图标按钮三件套**：title 属性（原生兜底）+ 自定义 **tooltip**（延迟 **400ms**、**focus 也显示**、**不遮挡触发元素**、**Esc 关闭**）+ **aria-label**（读屏命名）。**a11y 约束（AR-22 / AR-20，不放宽）**：tooltip 与 aria-label **同源**（同一 i18n key），禁止两套文案漂移；图标按钮 **Tab 可达**且焦点可见；tooltip 属 **L4 平台浮层**（AR-01），不得被 L2 WebView 覆盖；AR-20 门禁与核心任务键盘完成率不放宽，Mod+K 仍 100% 覆盖（§3.5）。**补偿机制**：tooltip（即时）+ Mod+K 命令面板（可检索）+ 渐进披露（情境化）+ 侧栏面板分区标题共同承担被砍掉文字的可发现性。

**终端软换行（AR-22 第 4 条 + AR-23 第 6 条）**：**默认开启**，超列宽在**视觉上折行**、**不产生横向滚动**；**语义不变（关键）**——**不改变字符内容、不改变网格列数、不改变复制结果**，复制取网格逻辑行（含全部字符），与视觉折行位置无关，折行不得向字符流插入换行、空格或续行标记；**续行提示**为极轻视觉提示（行首淡色标记/轻微缩进），属渲染装饰，**不写入屏幕内容、不参与选区、不被 AI 上下文当作字符读取**。**关闭软换行 = 视觉裁剪（AR-23 第 6 条）**：关闭后超列宽内容在网格右边界**被裁掉（clip）**，**仍然不产生横向滚动条**；理由是**真实终端网格由列数定义**——字符只存在于「行 × 列」坐标中，向右滚动视口是**日志查看器**语义，不属于终端网格，因此本规格在两个方向上都拒绝横向滚动。裁剪态不得造成内容能力丢失：复制仍取完整逻辑行、可一键临时开启软换行查看、AI 上下文完整性不受影响，且此取舍写入已知问题清单（§3.15）。**开关与取舍**：提供开关（配置 + 每会话覆盖，§7 UX-OQ-15），**代价**是超长单行折行后占用更多行、**降低单屏信息量**，这正是必须可关的原因；网格仍按行高 1.25 渲染（AR-14），块状光标与字符级选区不变，软换行与裁剪都是纯视觉层。

**滚动条与会话容积**：全局 **overlay 滚动条**——宽 **6px**、**无轨道**、**静止时不可见或极淡**、**hover 显现**、**不挤压内容**，样式由 token 驱动且两主题各自满足对比度；**终端任何情况下无横向滚动**（开=折行，关=裁剪；见上），网格自身不得出现横向滚动条；**Agent 面板长内容改为可折叠分区**，**默认展开 ≤2 个**，折叠状态持久化于会话；**布局容积（AR-23 / ADR-0017）**——**「工作区视图」已不存在**（AR-23 第 1 条），Workspaces 的资源视图在侧栏面板内以分区折叠 + 内部滚动容器承载，**侧栏面板与设置窗口都不得产生页面级滚动条**，基准窗口 1600×1000 与 1280×800 两档皆然。

### 3.13 组件分层（原生 vs Web，C1/C22，不变 + AR-23 落点）

| 层 | 允许内容 | 禁止 |
| --- | --- | --- |
| 原生（L1 chrome） | 受限控件集 ≤20：Box / Text / Icon / Scroll / Popover / Focus 环 + chrome 专用件（含 **tab「+」选择器浮层、侧栏 rail/panel、窗口控制三态按钮、设置窗口外壳**）；布局为纯函数 (tree, constraints) → rects | 不做表格、富文本、通用 UI 工具链 |
| Web（L2 面板） | React + TS strict + headless 原语 + CSS 变量（含 **Agent 分区对话内容、设置窗口内容页、Themes/Plugins/Audit 面板**） | 运行时 CSS-in-JS；缓存终端网格真相 |

组件必须声明 a11y 语义（role、焦点序、键盘可达），双栈各自映射平台 a11y API；AI 流式 token 按 ≥16ms 合帧后入 store（05-3.2）。**插件 UI** 只允许 Tier1 声明式 view schema（JSON，由 Host 渲染）+ token 子集 + 组件白名单，禁止帧内任意绘制、写 PTY/输出流、自建视觉。图标按钮、overlay 滚动条（§3.12）、**侧栏 rail 与设置窗口**必须同时提供原生与 Web 两侧实现，语义契约一致。

### 3.14 AI 视觉语法原语与风险色阶（C7，不变）

| 原语 | 用途 | 默认落点 | 风险色阶映射 |
| --- | --- | --- | --- |
| Inline Hint | 单行建议/提示 | 输入行上方或行内 | info / caution |
| Command Explain | 命令解释（流式） | **侧栏 Agent 分区** | info；含 L2/L3 时叠加 danger/destructive |
| Diff Block | 文件/配置差异 | Agent 分区为主，可内联 | add/del/ctx 三色 + 风险色 |
| Diagnosis Card | 故障诊断结论与下一步 | **侧栏 Agent 分区**（AR-17 首选能力） | 按诊断出的操作风险着色 |
| Risk Ladder | 风险等级与影响面阶梯 | dry-run 面板/审批流 | info → caution → danger → destructive |

**关键解耦**：AI 输出四色阶（info/caution/danger/destructive）表达**消息严重度**，与操作风险四级 L0–L3/U 是两套枚举；二者通过 risk.tier.* → ai.risk.* 的显式映射表连接，禁止混用同名色。**渲染与流式规则**：禁止自由 markdown 或原始 HTML 直出（渲染器为白名单注册表）；行数 >40 或被折叠的 diff **不计入**终端 scrollback；流式输出统一光标 + 「未完成」底纹，禁止逐字闪烁；destructive 的二次确认由组件强制实现，AI 与插件均不可绕过；跨会话引用（§3.8）以来源 chip 参与渲染，chip 用语义色而非风险色。**落点随 AR-23 修订**：原文中「侧栏」指右侧常驻面板，现统一指**左侧栏 Agent 分区**（按需展开，§3.6）；OQ-23 的「诊断/解释默认侧栏」口径同步指向 Agent 分区。

### 3.15 终端画质档位与已知问题（C20，不变）

| 项 | 规格 |
| --- | --- |
| 默认档 | 灰度抗锯齿 + hinting 关闭 + 严格网格对齐（误差 ≤0.5px） |
| 档位 | 「锐利」/「柔和」两档；「性能安全模式」一键关闭全部模糊与动效 |
| 行高 / 字号 | 行高默认 1.25（可调 1.0–2.0，**不适用 AR-22 的 1.5–1.6 UI 行高**）；字号 12–20 全档无错位 |
| 光标与选区 | 默认块状 + 200ms 呼吸（可关）、失焦变空心；选区 accent 30% 透明度，反白后文字对比度 ≥4.5:1（深/浅两主题都测） |
| 背景 | 模糊/透明默认关闭，仅在合成器支持且用户显式开启时启用 |

**已知问题清单（用户可在 UI 内查看，不得用模糊措辞掩盖）**：不承诺 ClearType 式 subpixel AA（Windows 观感可能弱于系统终端）；非整数 DPI 下的字形度量取舍；Linux 各发行版 WebView 渲染差异导致的 L2 面板观感差异；WebView 缺失时 L2 面板降级为原生文本面板（功能子集）；软换行下超长单行的单屏信息量下降（提供开关）；**软换行关闭时超列宽内容被视觉裁剪、不产生横向滚动（AR-23 第 6 条）**——复制仍取完整逻辑行，但屏幕上看不全；**窗口控制的位置与形态随平台而不同（macOS 左上圆点 / Windows·Linux 右上按钮）**，属 AR-23 的既定取舍而非缺陷。

### 3.16 主题格式、默认主题与安全约束（C19 不变 + AR-23 第 7 条）

| 字段 | 说明 |
| --- | --- |
| schemaVersion / id / name / author | 语义化版本，兼容 N-2 minor；稳定标识与展示名 |
| variants | dark / light / high-contrast / follow-system 覆盖集；**light 与 dark 均为官方一等主题**（AR-22），不再是从属变体 |
| tokens | 仅上述七组的 token 覆盖（键名必须在 schema 白名单内） |
| signature | 可选签名；未签名主题标记为 Untrusted |

**默认主题 = 跟随系统（AR-23 第 7 条，关闭 OQ-31）**：首次启动与用户未显式选择时使用 **follow-system**；系统不可判定（无 API、读取失败、与高对比设置冲突）时**回退深色**，并记录一次可查日志；用户选择一旦落地即覆盖默认值并随配置持久化（AR-09）。**浅色仍是与深色同等的一等主题**；**深 / 浅两套都进 P0 对比度与视觉回归门禁**（A24 / UX-G3 / UX-G4）。**安全约束**：主题是**纯数据**，禁止脚本、禁止自定义 CSS 注入、禁止 URL 引用与外部资源加载；导入必须经 JSON Schema 校验；失败时报错必须定位到「哪一行/哪個 token 非法」；官方提供 Dark / Light / High-Contrast 三套 + 跟随系统（含 Windows/macOS 独立监听与定时切换）；主题格式与主题商店永久免费开放，本地导入不经审核（过审仅用于 Verified 标记）；**主题不得降低对比度门禁**（C18）。**跨窗口联动**：Themes 分区与设置窗口的主题切换都必须即时作用于所有已打开窗口（§3.3），不得要求重启。

### 3.17 可访问性契约与诚实边界（AR-20，不变 + AR-23 新增）

| 承诺 | 范围 | 度量 |
| --- | --- | --- |
| UI 层全流程可达 | Tab / Pane 树、**侧栏 rail 与 7 个分区面板**、**设置独立窗口**、对话框、命令面板 | NVDA 与 VoiceOver 各完成 6 条核心流程；WCAG 2.2 AA |
| 核心任务键盘完成率 | 开 Tab、分屏、切 Workspace、恢复会话、调用 AI、**新建终端（tab「+」选择器）** | 100%（自动化用例 + 人工复核） |
| **侧栏与窗口可达性**（AR-23 新增） | rail 7 分区 + panel 内容 + 底部 Settings/收起；设置窗口、窗口控制三态按钮 | **7/7 分区**可纯键盘进入并操作、收起态 rail 全部可达；窗口控制可聚焦可键盘触发、aria-label + tooltip 100%、关闭后焦点回到触发处 |
| 对比度 | 全部主题正文 ≥4.5:1；官方主题目标 ≥7:1 | CI 校验全部官方主题（C18），**深/浅两主题都测** |
| 减动与焦点 | prefers-reduced-motion 下动画 = 0（≤16ms）；焦点可见且不被网格吞掉、焦点序与视觉序一致 | 自动化断言 + 键盘遍历用例 |
| 图标按钮（AR-22 新增） | 100% 带 title + aria-label；tooltip 键盘可达 | 静态检查 + 键盘用例（A18/A19） |

**诚实边界（不承诺）**：不做 TUI 语义树解析；对 TUI 只承诺 raw 输出朗读 + 「应用模式」切换（把 TUI 当纯文本流朗读）。原生网格与 WebView 双栈各自映射平台 a11y API，语义契约（role、焦点序、命名）由本规格统一声明（§7 UX-OQ-8）。**tooltip 只是增强，读屏命名始终由 aria-label 承担**（AR-22）。**布局重构不降低 a11y 承诺**（AR-23 明确不改 AR-20）：侧栏与设置窗口从第一版起就必须有 role、焦点序与键盘路径。

### 3.18 i18n 与 RTL（C21，不变 + 侧栏位置项）

- **v1 即 ICU MessageFormat**；单一消息目录编译为 Rust 与 TS 双产物，禁止两栈各维护一份文案。
- 禁止片段拼接；带复数/性别/单位的长句走 ICU select/plural；数字、日期、单位、键盘符号（Mod → Cmd/Ctrl）按 locale 解析。
- **伪本地化（pseudo-locale）截图进 CI**；**去文字后 tooltip 文案更长**，伪本地化必须覆盖 tooltip 与 aria-label（含 rail 分区 tooltip 与窗口控制 tooltip）。
- 插件 i18n：插件在 manifest 声明自身资源包，Host 合并命名空间；插件不得覆盖核心文案键。
- **RTL 不阻塞 v1**：布局用 logical properties 预埋；**侧栏的「左 / 右」设置项是 RTL 的主要用途**（AR-23：默认左，右仅作偏好与 RTL）；网格内 bidi 必须走 Unicode Bidi 算法（先保读取正确性）；终端 BiDi 的写入/光标语义为受限范围，须在 UI 内明示支持边界。

### 4.2 对外契约

| 契约 | 形式 | 约束 |
| --- | --- | --- |
| **布局与窗口契约**（AR-23 / ADR-0017 新增） | 侧栏分区表（7 分区 + 底部 Settings/收起）+ 窗口控制位置枚举（follow-platform / macos / windows） | 分区集合固定，新增能力必须落进七分区之一；窗口控制三态行为跨平台一致，仅位置与形态随平台 |
| Action Registry | 稳定 action id + i18n key + 默认键位 + 可见性 + 风险等级 | Mod+K 覆盖率 100% 的唯一真相源；同一契约经 Local API/CLI 暴露（DC-24）；图标按钮、rail 分区、选择器条目、窗口控制必须注册并可被 Mod+K 检索 |
| 主题格式 | JSON + JSON Schema + schemaVersion + 可选签名 | 纯数据、兼容 N-2 minor、错误定位到 token；light/dark 均为一等；默认 follow-system |
| AI 输出 / Agent Scope 契约 | 版本化结构化事件（原语 + 风险 + 依据）+ 作用域 / 参与会话集合 / 提升降级来源 | 破坏性变更走 capability 协商（AR-04）；只读跨会话与写作用域可区分、审计可回放 |
| i18n 资源 | ICU MessageFormat 目录 | 单源双产物；伪本地化可测；tooltip 与 aria-label 同源 |
| 插件 UI | Tier1 view schema + token 子集 + 组件白名单 | 零代码执行、零视觉漂移 |

### 4.3 禁令（与 HARNESS §4.4 一致 + AR-23）

L0/L1 不得依赖 L3/L4；前端不得直读终端内存或缓存网格真相；AI 不得产出可执行字符串直出 shell；禁止裸 HTML / 自由 markdown 渲染；主题不得含脚本或 CSS 注入；WebView 不得覆盖 L4 原生浮层（含 IME 候选窗、右键菜单、tooltip）；**禁止用 emoji 作 chrome 图标**（AR-22）；**P2 禁止开放任何跨会话写操作**（AR-22）；**主区不得被任何非终端视图占用，禁止引入「终端 / 工作区」视图切换**（AR-23 第 1 条）；**顶栏不得出现「连接主机 / 新建工作区」**（AR-23 第 4 条）；**软换行关闭时终端不得出现横向滚动条**（AR-23 第 6 条）。
