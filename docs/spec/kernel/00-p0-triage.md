## 5. 必须拍板清单（A 档，共 10 条 ≤ 12 上限）

### A1 · OQ-VT-03｜xterm 用例基数与覆盖口径
- 候选 ①：≥2000 条，ctlseqs 每条目 ≥1 用例 + 真实语料 ≥20%（分册建议）。代价：语料建设约 4–6 人周 + 长期维护。
- 候选 ②：不做 ctlseqs 1:1，只做真实语料回放 ≥99%。代价：差异表膨胀，「跑不动就绿灯」回潮（§7-D 已被否决）。
- 候选 ③：ctlseqs 1:1，但把覆盖口径降级为差异预算（全局 ≤25 项 / 单 minor ≤10）。代价：覆盖面与差异预算脱钩，V-04 数字不可解释。
- **推荐 ①**：G1 的 ≥99% 只有在用例集可复现、可解释时才可信；②③ 会把门禁数字变成不可审计的橡皮章。

### A2 · OQ-VT-09｜默认 `$TERM` 与 terminfo
- 候选 ①：v1 默认 `xterm-256color` + 随包 `termai` terminfo，P2 评估切换（分册建议）。
- 候选 ②：v1 即默认 `termai`。代价：用未经验证的 terminfo 直接承担 PTY-AC-05 的 7 应用 × 2 平台矩阵。
- 候选 ③：v1 只发 `xterm-256color`，不发 `termai` terminfo。代价：失去提前暴露能力协商问题的通道。
- **推荐 ①**：apps 探测面零变化，同时把能力通道提前铺好；② 把 P0 兼容门禁押在未验证 terminfo 上。

### A3 · OQ-PTY-01｜conpty-rules owner 与豁免期
- 候选 ①：T1 内核（termai-pty）+ T5 复核；每条规则带 owner + expires（默认 2 minor）（分册建议）。
- 候选 ②：平台组独占 owner，内核只读。代价：内核无法自证改写，K-04 双签失效。
- 候选 ③：发布工程 owner，随 release 批量清理。代价：与 CODEOWNERS 边界冲突，豁免无期限。
- **推荐 ①**：conpty-rules 是 AR-25.3 的门禁真源，owner 必须与「改写登记 + 门禁判定」同一责任体。

### A4 · OQ-INP-01｜§5 是否增设「输入正确性」行
- 候选 ①：新增一行，门禁 = IN-AC-04/07/09/10 全绿，目标 = IN-AC-08（分册建议）。
- 候选 ②：新增一行，但门禁只收可自动化的 IN-AC-07/09/10；IME（IN-AC-04）留 L6 + 人工会签。
- 候选 ③：不新增，维持 §8.2 主题验收。代价：输入正确性无发布阻断点，与 A2「兼容性是入场券」不符。
- **推荐 ②（次选 ①）**：IN-AC-04 是「人工 + 脚本」项，把它设为发布阻断点等于把 P0 出口押在不可自动化的截图矩阵上。

### A5 · OQ-INP-06｜Wayland text-input-v3 的 v1 级别
- 候选 ①：P0 只要求 X11/fcitx5 preedit 可用；Wayland 无协议时登记偏差 + UI 明示，不计失败（分册建议）。
- 候选 ②：Wayland 无 `text-input-v3` 即 P0 失败（矩阵口径最严）。代价：主流 Linux 桌面被挡在 P0 之外。
- 候选 ③：v1 明确不支持 Wayland IME，写入「不做」清单。代价：丢失诚实降级路径，与 AR-20 张力。
- **推荐 ①**：与 ADR-0014 差异登记机制一致，同时满足 AR-20 诚实原则。

### A6 · OQ-INP-12｜粘贴可配置边界
- 候选 ①：判定粘贴为「用户发起来源」、非破坏性外发 → 可配置；消毒与审计不可关（分册建议，需安全会签）。
- 候选 ②：粘贴确认视同 AR-06，**不可由配置关闭**。代价：括号粘贴未激活时的多行粘贴摩擦上升，盲确认率可能反而升高。
- 候选 ③：可配置但**只能加强**：`ask` 可升 `always`，不得降 `never`；消毒与审计不可关。
- **推荐 ③**：与 AR-06「企业策略只能加强不能削弱」同一逻辑，且不破坏 AR-29.5「不允许静默多行」；① 留下降级口子。

### A7 · OQ-PM-01｜安装包 artifact 口径
- 候选 ①：按平台主格式计（Win MSI / macOS DMG universal2 / Linux AppImage），任一超限即 FAIL；macOS 超限改 thin slice + 双下载（分册建议）。
- 候选 ②：只按单一最小产物（Linux AppImage）计。代价：macOS 实际脱离门禁。
- 候选 ③：把门禁从 60MB 改为「三平台压缩后总和」。代价：实质放宽 §5，需 ADR + TSC。
- **推荐 ①**：不改 §5 数值，且给 universal2 明确兜底；②③ 都会削弱门禁。

### A8 · OQ-PM-04｜参考机不可用时 PR 政策
- 候选 ①：按路径范围判定；不触及 `term-{render,gpu,vt,session,pty}` 的 PR 可 `SKIP(no_hotpath)`（分册建议）。
- 候选 ②：任何 PR 都不得 SKIP；参考机不可用即阻断合并。代价：文档类改动也停摆。
- 候选 ③：所有 PR 都 SKIP，发版前统一跑全量。代价：等于取消 G4-PR。
- **推荐 ①**：与 ADR-0014「门禁项标 INCONCLUSIVE、不得用云 runner 顶替」一致，且不牺牲热路径覆盖率。

### A9 · OQ-PM-07｜MAD/中位数分级
- 候选 ①：按指标族分级（帧时 5% / 启动 3% / 吞吐 2% / RSS 1%）（分册建议）。
- 候选 ②：全部保持 ≤2%。代价：P99 类指标 run-to-run 离散大，门禁随机红。
- 候选 ③：全部放宽到 5%。代价：掩盖吞吐回归。
- **推荐 ①**：分级只改统计窗口不改门禁数值语义；②③ 都在两个极端上牺牲可信度。

### A10 · OQ-PM-08｜1GB 吞吐语料分片权重
- 候选 ①：入库即冻结，权重变更需 ADR（分册建议）。
- 候选 ②：权重可变，只要切片 SHA-256 对得上。代价：门禁含义可漂移，跨版本不可比。
- 候选 ③：取消分片权重，改单一合成语料。代价：丢掉真实语料覆盖（K-08 已否决把语料提交进 git）。
- **推荐 ①**：权重直接决定 ≥500MB/s 的含义，冻结才可解释。

| 条目 | 误判为 B 的常见理由 | 变成 A 的判据（触发条件） | 后果 |
| --- | --- | --- | --- |
