# 07 AI / Agent 工程负责人评审

## 一、角色立场与判断依据

立场：AI 层是终端的**操作协处理器**，不是自治主体。目标是压缩"从意图到正确命令、从报错到修复"的摩擦，而非替用户决策。

三条公理（后续结论均由此推导）：
1. **延迟是生死线**：终端用户肌肉记忆强，超过 800ms 的交互即破坏心流；AI 必须在不打断的前提下增益。
2. **终端是破坏性环境**：rm -rf、push --force、kubectl delete 不可逆，写操作默认授权等于产品级事故。
3. **模型能力年际更迭**：必须模型无关、可插拔、BYO-key 一等公民。

推论：**能用规则、索引、静态分析解决的不调用模型；调用模型之处必须可解释、可撤销、可验证。**

## 二、关键结论

**D1 架构＝单 Agent 主循环 + 受控子 Agent 委派，不做多 Agent 编排框架。**
理由：终端任务粒度小、时延敏感，多 Agent 的消息开销与不确定性远大于收益；子 Agent 只用于可并行的检索、多仓库调查、长日志分析。
代价与取舍：放弃"多专家协作"叙事；复杂运维只能靠工具扩展，不能靠 Agent 数量。

**D2 上下文＝结构化事件流（Context Bus），不做字符串拼接。**
理由：只有结构化才能裁剪、脱敏、回放、eval；字符串拼接是隐私过滤与评测的坟墓。
代价：初期工程量与 schema 治理成本高。

**D3 模型＝混合路由 + BYO-key 一等公民。**
理由：成本、延迟、隐私三者不可兼得，只能按任务分层。
代价：需维护本地与云端两套 prompt 与降级路径，且路由本身会误判。

**D4 权限＝Capability + 风险四级 + 三档授权（once / session / rule）。**
理由：终端必须默认只读、写操作显式、习惯可固化。
代价：首次摩擦上升；规则系统本身成为攻击面。

**D5 shell 执行放在独立 watchdog 进程 + shell AST 预分析。**
理由：安全边界与 UI 稳定性；AST 支撑风险分级与 dry-run 改写。
代价：需为 bash/zsh/pwsh/fish 维护解析器，必然存在解析失败，此时按更高风险保守处理。

**D6 差异化价值排序：故障诊断 > 上下文感知命令生成 > 大规模运维。**
理由：诊断是 AI 独有、补全类产品做不到；命令生成高频但会被 shell 补全蚕食，不能作为唯一护城河；大规模运维是 Ansible/K8s 控制面战场，与终端本体正交。
代价：早期放弃"AI 运维平台"叙事，聚焦单机、单会话纵深。

**D7 记忆分三层：会话 / 项目（.termai/）/ 全局，默认本地、可见可删。**
理由：终端上下文强项目相关，隐私与合规要求可删除。
代价：无云端记忆，跨设备一致性弱。

**D8 评测先行：AI 功能合入必须带离线 eval 与回归集。**
理由：没有 eval 的 AI 功能不可维护。
代价：拖慢 demo 节奏，前期投入重。

**D9 工具层自研 ABI + 兼容 MCP，不自建协议生态。**
理由：生态是网络效应，自研必输；差异化应在 UX 与上下文质量。
代价：受 MCP 演进节奏牵制，需自建安全网关。

**D10 AI 不可用时应是"更好的终端"而非残缺终端。**
理由：终端必须 100% 可用，AI 只是增益层。
代价：AI 与内核必须彻底解耦，架构成本上升。

## 三、详细设计

**3.1 差异化定位**：招牌能力是"贴一段报错 → 结合 cwd、shell 版本、git 状态、最近 200 行输出给出因果链与修复动作"。明确不做：通用聊天窗、代码编辑器、自然语言 Todo。

**3.2 工具层**：统一 Tool ABI：name / json_schema / risk / idempotent / timeout / approval_policy / render_hint。工具集：shell.exec（交互式 PTY、超时、输出截断）、fs.*、git.*、container.*（包装 CLI，不重写 SDK）、net.fetch（默认禁网 + 白名单）、mcp.*（独立进程沙箱）。工具输出统一 envelope：stdout / stderr / exit_code / truncated / artifacts，而非裸文本。

**3.3 上下文工程**：采集 cwd、shell 与版本、OS/arch、近 N 条命令及 exit code、结构化 scrollback、失败 stderr、git status/diff/branch、repo 树与构建文件、容器上下文、--help。预算 8k–32k token，优先级：当前报错 > 近 20 条命令 > git 摘要 > 目录树 > 帮助文本；超预算用模板化压缩（去重、频率折叠、保留首尾与异常行），模型摘要仅兜底且必须缓存。Redaction 前置在本地（AK/SK、token、私钥、连接串、密码、敏感 env），云端 payload 可在 UI 中预览回看。

**3.4 模型路由**：意图分类与"是否需要 AI"走本地小模型，P95<50ms；命令建议本地或轻量云，P95<300ms；命令生成与解释走云大模型，首 token<1.5s；诊断与多步计划走云大模型 + 工具循环，首 token<3s。缓存按 (prompt_hash, 上下文摘要 hash, 模型)；离线时只提供本地补全与基于错误码的规则解释，**不做诊断幻觉**；支持日/月 token 上限与"仅本地"模式，超限明示降级。

**3.5 检索**：代码库以 tree-sitter 符号索引 + ripgrep 为主（精确、可解释、无漂移），embedding 仅作自然语言补充；命令历史用结构化 + BM25 + 向量混合，必须支持按 cwd/repo 过滤；man/--help 本地缓存。向量库用本地嵌入式，不上托管服务。

**3.6 命令安全闭环**：意图 → 生成 → 解释 → 风险分级 → dry-run 或改写 → 审批 → 执行 → 验证 → 有界修复。风险四级：L0 只读 / L1 可逆写 / L2 难逆 / L3 高危。L2、L3 必须展示 AST 影响面（路径、远端、影响条数）并确认，L3 需输入确认短语。失败修复最多 2 轮，每轮必须改变假设，禁止盲重试。AI 不得自行提权或绕过审批。

**3.7 注入防护**：数据与指令分离，外部内容（文件、工具输出、网页、MCP 返回）一律包不可信信封；工具调用必须经 Policy Engine 二次校验，模型"说执行"不等于执行；MCP 独立进程、最小权限、网络白名单、可审计；维护注入用例集纳入 CI。

**3.8 记忆**：会话层（滚动摘要 + 关键事实）、项目层（仓库内 .termai/memory，可选提交）、全局层（模型、风险容忍、审批习惯）。全部可见、可编辑、可删除，不做隐式画像。

**3.9 评测**：离线任务集按 shell/OS 分桶，双指标（语义正确率 + 危险命令率）；在线看采纳率、审批通过率、回滚率、诊断修复率、TTFT、token/次、AI 关闭率；prompt、模型、工具变更必须跑固定集，**危险命令率上升即阻断合入**；每周人工抽样 50 条真实会话。

## 四、与其他角色的接口与依赖

| 对方 | 我必须得到 | 我承诺 |
|---|---|---|
| 内核 / VT | 结构化 scrollback（属性 + OSC 133 命令边界 + 时间戳）、PTY 生命周期事件 | 不在内核塞 AI 逻辑；AI 关闭时零开销 |
| UI / 渲染 | 内联建议、审批卡片、风险与 diff 面板、流式渲染 | 稳定事件 schema 与背压，不阻塞主线程 |
| 平台 / 插件 | 插件可注册工具与上下文单元、沙箱权限 API | 版本化 Tool ABI |
| 安全 | redaction 规则、密钥识别、审计规范 | 出网 payload 全量可审计、可预览 |
| 商业化 | BYO-key 与私有部署边界、许可输入 | 见下方许可立场 |

**许可立场（明确表态）**：核心与 AI 运行时用 Apache-2.0 / MIT 开源，插件生态开放；云端托管、团队协作、企业策略管控作为商业增值。终端是信任品，闭源核心拿不到插件生态。**这与"核心闭源 + 插件市场抽成"派直接冲突，请 Orchestrator 仲裁。**

## 五、被否决的方案与反方意见

| 方案 | 否决理由 | 反方意见与我的让步 |
|---|---|---|
| 多 Agent 编排（Planner/Executor/Reviewer） | 时延与不确定性远大于收益 | 复杂运维确需分工 → 预留子 Agent 接口，默认关闭 |
| 全量 embedding 代码库 RAG | 昂贵、漂移、不可解释 | 语义检索体感好 → 作为可选增强，不进默认路径 |
| AI 调度逻辑放进内核 | 违反 D10，崩溃或卡顿会拖垮终端 | 性能与集成度更好 → 若能做到硬隔离与零开销可重评 |
| 云端记忆 / 强制登录 | 隐私、离线可用性、企业合规 | 跨设备是真需求 → 作为可选企业功能 |
| 自研竞品协议 | 生态网络效应，自研必输 | MCP 安全模型薄弱 → 自研安全网关、协议兼容 |
| 零确认自动执行 | 一次事故摧毁信任 | 确认破坏心流 → 信任模式下可放行 L0/L1，L2 以上永不豁免 |

## 六、风险与缓解

| 风险 | 缓解 |
|---|---|
| 幻觉生成高危命令 | 风险分级 + AST 影响面 + 强制审批 + CI 门禁 |
| 延迟破坏心流 | 本地优先路由、缓存、流式、AI 可完全关闭 |
| 上下文泄漏密钥 | 本地 redaction 前置、出网预览、审计 |
| 提示注入越权执行 | 数据指令隔离、Policy Engine 二次校验、注入回归集 |
| 成本与窗口失控 | 分层预算、压缩、缓存、用户上限 |
| 供应商锁定与模型更迭 | 模型无关抽象、BYO-key、路由可插拔 |
| 跨平台 shell 解析差异 | 解析失败时按更高风险保守处理 |
| eval 不足导致静默退化 | 双指标门禁、在线告警、每周人工抽样 |

## 七、可验证验收标准（量化）

1. 延迟：本地意图分类 P95<50ms；命令建议首 token P95<300ms；诊断首 token P95<3s。
2. 质量：内部 TermBench 命令生成 Top-1 语义正确率 ≥75%；故障诊断可操作修复率 ≥60%。
3. 安全：L2/L3 未经审批执行次数 = 0；红线用例 100% 拦截；注入用例拦截率 ≥95%。
4. 隐私：固定密钥样本集出网命中率 = 0；100% 出网请求可在 UI 中回看。
5. 降级：断网或 AI 关闭时，终端核心功能可用性 100%，P95 时延劣化 <5%。
6. 工具层：所有工具声明 schema、风险级别与超时；外部 MCP 工具默认无网络。
7. 记忆：任一条记忆可在 3 次点击内查看并删除。
