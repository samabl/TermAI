# TermAI 用户体验与交互总纲（UX Research & Interaction Lead）

终裁人：资深用户研究 & UX 交互负责人。本文是决策记录，每条结论附带被牺牲的代价。

## 一、角色立场与判断依据

1. **用户不能容忍的不是慢，而是被降级**：管道、脚本化、退出码可见、纯文本可复制、无鼠标完成一切是终端本命。
2. **终端里最稀缺的是注意力焦点**：AI 若无明确收益而制造第二焦点，用户会永久关闭且不复开。
3. **信任来自可预测性而非智能**：能预判、能收回、不执行也能看懂。

我的代价：拒绝全屏 Chat 牺牲演示冲击力；选 WebView 被性能派指责；拒绝逐条确认被安全派指责；风险分级被效率派指责啰嗦。

## 二、关键结论

**D1｜AI 分层范式、顺序固定。** 结论：?? 内联 Agent 为第一入口，侧边面板为主场，ghost text 只补全，全屏 Chat 降为面板次级模式，整行预测默认关。理由：单入口必在某类用户身上失效。代价：四套入口的一致性与 a11y 维护成本。

**D2｜选 B：Rust 核心 + WebView UI，终端网格走原生 GPU 层。** 理由：IME、RTL、屏幕阅读器语义树、字体回退、剪贴板是交互地基，自研原生重建需数年且不构成差异化；差异化在 PTY/VT 正确性、AI 上下文与插件生态。代价：包体膨胀，双层的焦点与输入法同步 bug 是长期负债。

**D3｜风险闸门用确定性规则，模型只做辅助。** 理由：模型置信度在破坏性命令上不可信、不可回归测试。代价：规则必然误报、老手被拦，「本会话信任」出口本身就是安全缺口。

**D4｜会话即本地文件，默认零云同步。** 理由：历史含密钥、内网地址与生产拓扑，默认上传即信任自杀；全量落本地 SQLite 与明文日志。代价：跨设备体验差，须顶住「同步换账号」的诉求。

**D5｜键盘优先 = 命令面板 100% 覆盖，可发现性靠可粘贴兜底。** 理由：老手的可发现性来自「任何东西都能变成可复制文本」，不是 tooltip。代价：面板会功能膨胀，需人工排序治理。

**D6｜拒绝逐条确认，改四级风险 + 差异化摩擦。** 理由：确认疲劳导致 5 秒内盲确认，安全性反低于「无确认 + 可撤销」。代价：红色命令仍可能被盲确认，靠二次输入目标名压制。

**D7｜内核 Apache-2.0，UI 与 Agent 编排 AGPL-3.0，插件 API 永久开放。** 理由：内核是生态入口须最宽松，编排层是商业边界须有传染性。代价：法务阻力、社区抵触、竞品白嫖内核——接受。

**D8｜不做欢迎向导，做情境化教学。** 理由：开机导览跳过率极高。裁决：首屏即输入、零弹窗，教学只在首次报错与首次危险命令时出现。代价：AI 能力发现率低。

## 三、详细设计

### 3.1 画像与关键旅程（失败即死的点）

| 画像 | 旅程 | 失败即死 |
| --- | --- | --- |
| 应用开发 | 起服务→看日志→改码→重跑 | 大输出卡顿；报错无法带上下文问 AI |
| SRE | 多机 tail→定位→修复 | 确认疲劳；分不清生产/预发；无审计 |
| 数据/AI 工程 | 提交长任务→监控→看产物 | 丢焦点；断连丢上下文 |
| CLI 重度用户 | 管道、脚本、别名 | AI 干扰原始输出；复制出的命令别处跑不通 |
| 终端爱好者 | 配置、主题、插件 | 配置不可编程；插件沙箱慢 |

### 3.2 信息架构与交互模型

- 三层：**Workspace（持久化单元）> Tab（任务/主机）> Pane（分屏树，上限 8）**，布局连启动命令存为模板。
- 三个「会话」分开命名：**PTY Session**（进程与缓冲）、**Agent Session**（模型上下文与工具权限）、**Workspace**（磁盘）；UI 禁止笼统用「会话」。
- 恢复语义：还原 cwd、env、布局、滚动位置与历史，**绝不自动重放命令或重启进程**。
- 命令面板：Cmd+K 全局动作、Cmd+Shift+P 命令簿、Cmd+P 快速打开（文件/主机/容器）、Cmd+Enter 把输入交给 AI。

### 3.3 AI 交互范式终裁

| 范式 | 触发 | 适用 | 主要失败模式 | 裁决 |
| --- | --- | --- | --- | --- |
| ghost text | 输入时 | 命令名、路径、分支、容器名补全 | 幻觉参数被 Tab 误接受 | **保留；只补全不生成副作用命令，接受前整行可审阅** |
| 整行灰字预测 | 空闲时 | 重复性任务 | 噪音、打断心流、被永久关闭 | **默认关闭** |
| 侧边 Agent 面板 | 显式打开 | 多步任务、解释报错、跨会话调查 | 抢宽度、注意力分裂 | **主场**；右侧、宽度 ≤ 40%，可收成徽标 |
| 全屏 Chat | 面板内切换 | 长教学、方案讨论 | 脱离上下文、复制损耗 | **不做主范式**，仅次级模式 |
| 内联 Agent（?? 前缀） | 行首 ?? | 老手快速生成 | 发现性差、与 shell 冲突、污染脚本化 | **第一入口**；结果落输入行由人确认，历史中不伪装成手输 |

### 3.4 信任与安全交互

| 等级 | 判定 | 交互 | 可撤销性 |
| --- | --- | --- | --- |
| L0 只读 | 无写副作用 | 直接执行并标注 | 不适用 |
| L1 幂等写 | 工作区文件、git 可逆 | 执行 + 事后撤销提示 | 快照 / git 引用 |
| L2 破坏性 | rm -rf、force push、drop、kubectl delete | 先 dry-run，确认须带目标名 | 部分可撤销 |
| L3 不可逆/外部 | 生产集群、云 API、密钥 | 二次输入目标名 + 环境色带 | **不可回滚徽章** |
| U 不可判定 | 脚本、动态拼接、黑盒 | 按 L2 起步并说明原因 | 无承诺 |

原则：**解释优先于警告**；撤销栈只覆盖工作区文件与 git 可逆操作，绝不承诺 OS 级回滚。

### 3.5 错误体验与 onboarding

- 错误是一等公民 artifact：保留原始 stderr、exit code 与所在 Pane，附「AI 解释」「带上下文提问」「复制为 issue」；**永不吞 stderr、永不美化退出码**。
- 连接失败须区分网络不可达 / 认证失败 / 远端命令失败，各给不同下一步。
- 渐进披露：L0 零配置即普通终端；L1 命令面板即学习入口；L2 ?? 与面板；L3 模板与插件 API。**关掉 AI 后仍是完整终端**，列为回归项。

### 3.6 可访问性、i18n 与 RTL

- **诚实边界**：承诺 UI 层（Tab/Pane/面板/设置）对 NVDA、VoiceOver 全流程可达；对 TUI 只承诺 raw 输出朗读 + 「应用模式」切换，**不承诺语义化 TUI**。
- 硬指标：核心任务 100% 键盘可达；对比度 ≥ 4.5:1；动效响应 prefers-reduced-motion；焦点可见且不被网格吞掉。
- i18n：v1 即用 ICU MessageFormat；布局用 logical properties 为 RTL 预埋；**RTL 镜像不作 v1 阻塞项**，但网格内 bidi 文本须走 Unicode Bidi 算法。

## 四、与其他角色的接口与依赖

| 对象 | 我必须得到 | 我承诺 |
| --- | --- | --- |
| 内核/渲染 | 网格原生渲染 API（滚动、选择、a11y 坐标映射）、60fps、IME 与焦点契约 | 接受双层复杂度，提供性能与崩溃用例 |
| AI/Agent | 风险规则接口与可回归测试集、流式输出可中断语义 | 四类入口的失败模式验收 |
| 安全 | 威胁模型与「不可回滚操作清单」 | 拒绝无差别确认，改分级摩擦 |
| 插件生态 | 插件 UI 能力边界与权限声明格式 | 权限提示规范与完整禁用路径 |
| 数据/埋点 | 本地优先、可一键全关、无 PII 的遥测 | 北极星与护栏指标定义 |
| Orchestrator | 对 D1/D2/D6/D7 的冲突仲裁 | 量化验收标准与反方意见记录 |

## 五、被否决的方案与反方意见

1. **全屏 Chat 作主入口**——反方（增长/AI）：最易演示。否决：与终端上下文割裂、复制损耗、制造第二焦点。复议：面板对话留存显著更高。
2. **A 自研 wgpu + 原生 UI 工具链**——反方（工程洁癖派）：无抖动、包体小、控制力满分。否决：a11y、IME、RTL、剪贴板、字体回退的重建成本被低估且不产生差异化。复议：WebView 达不到 60fps 或输入延迟 > 16ms。
3. **C Electron + xterm.js**——反方（速度派）：生态成熟、一周出原型。否决：内存与启动代价、VT 正确性天花板伤「快、稳」。
4. **危险命令逐条确认**——反方（安全派）：最稳妥。否决：盲确认率会上升，改二次输入。
5. **默认云同步历史**——反方（产品/增长）：账号体系与跨设备。否决：终端历史高敏感。
6. **欢迎向导**——反方（新用户增长）：降低首次理解成本。否决：高跳过率、污染首屏。

## 六、风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| AI 入口过多致认知过载 | 用户放弃全部 AI | 固定入口顺序；每季度砍最低使用率入口 |
| 风险规则误报 | 老手静默关闭提示 | 可审计的规则命中说明 + 「本会话信任」出口 |
| 双层 IME/焦点/选择 bug | CJK 用户直接弃用 | CJK 输入法回归矩阵进发版门禁 |
| 撤销边界被误解为万能回滚 | 一次事故即信任崩塌 | 徽章表达不可回滚；范围在 onboarding 明示 |
| 可访问性后置 | 后期重构成本爆炸 | a11y 契约前置到组件库，冒烟测试进 CI |
| 命令面板功能膨胀 | 可发现性反降 | 人工维护排序与分组白名单 |

## 七、可验证验收标准

1. 冷启动到可输入 ≤ 100ms（P95，三平台）。
2. 新用户 TTFC（到第一条有效命令）≤ 3 分钟且零弹窗。
3. 命令面板功能覆盖率 = 100%（CI 校验动作表与 UI 菜单差集为空）。
4. 核心任务（开 Tab、分屏、切 Workspace、恢复会话、调用 AI）键盘完成率 = 100%。
5. AI 建议接受率 25%~40%；红队测试集中**危险命令误执行率 < 0.5%**。
6. L2/L3 确认弹窗出现后 5 秒内直接确认的比例 < 15%。
7. 以关闭 AI 的 Launch flag 运行，终端基础功能回归 100% 通过。
8. 对比度 ≥ 4.5:1；reduced-motion 下动画为 0；NVDA/VoiceOver 完成 UI 层 6 条核心流程。
9. 4K 下持续 10MB/s 输出，帧率 ≥ 60fps、回显延迟 ≤ 16ms。
10. 12 人常驻面板（覆盖 5 类画像）+ 每两周 dogfood 埋点 + 每版本 8 人可用性测试（成功率 ≥ 85%）。

## 八、待决议问题（Open Questions）

1. D2 若基准测试打平，WebView 与自研原生之争由谁终裁？
2. 撤销栈是否覆盖容器内与远端文件系统？若不覆盖，L2 是否降级为「部分可撤销」。
3. 「本会话信任此模式」有效期：会话级、Workspace 级还是永久？
4. 插件能否自行渲染 AI 面板 UI？允许则一致性崩塌，不允许则生态受限。
5. 遥测默认开还是关？我倾向默认关 + 首次价值交换式征询。
6. RTL 镜像是否列为 v1 阻塞项？我主张不阻塞，需阿拉伯语/希伯来语实测支撑。
