# 08 · 安全 / 隐私 / 合规架构师

## 一、角色立场与判断依据

我的立场是**默认不信任（Zero Trust）**。PTY 输出、文件、Git 历史、网页、模型文本、插件代码皆不可信；AI Agent 不是可信执行者，而是**持有工具能力的不可信主体**。

依据：终端聚集用户最高价值资产（SSH 私钥、云 token、kubeconfig、连接串、生产凭据、源码）；AI 一接入，攻击面从"守一个本地进程"变成"守全部生产环境"，损害常常不可逆，不能用"概率低"定价。

三条红线：① 无人类显式批准，AI 不得执行破坏性（删除/覆盖/提权/写生产）或外发型（出站网络、git push、云 API）操作；② secret 永不进入模型上下文、不明文落盘、不进日志与遥测；③ 本地优先，scrollback/历史/文件默认不出设备，上传须 opt-in、可撤销、可审计。

取舍：我接受配置更啰嗦、自动化受限、插件门槛更高、不能复用 GPL 生态；拒绝为"开箱即爽"降低安全默认值。

## 二、关键结论

| # | 结论 | 理由 | 代价与取舍 |
|---|---|---|---|
| D1 | **capability-based + 默认拒绝**：插件身份 × 工具/资源 × 会话范围，企业策略可覆盖用户授权 | ACL 不足以描述插件组合 | token 签发/吊销复杂，SDK 门槛升高 |
| D2 | 落地"AI 执行命令七条黄金规则"（§3.2） | 提示注入不可根除，只能在能力层收口 | 自动化率下降 |
| D3 | Secret 永不进入 AI 上下文，脱敏在**上下文构建器内**完成 | 不依赖模型自律，本地模型也落日志 | AI 不能直接读 `.env`，须走受控引用 |
| D4 | 数据本地优先，遥测/崩溃上报 opt-in 可自托管 | 终端数据默认含机密，GDPR 要求最小化 | 失去默认遥测，定位变慢 |
| D5 | 插件须进程隔离 + 签名 + 权限清单，WASM 仅为额外防线 | WASM 宿主接口一宽即裸奔 | 插件性能与互操作变差 |
| D6 | 审计日志 append-only + 本地哈希链，可导出 SIEM，日志本身脱敏 | 必须不可抵赖，"是 AI 删的"不成立 | 存储开销，取证与隐私冲突 |
| D7 | 核心与 SDK 用 Apache-2.0/MIT 双许可，拒绝 GPL/AGPL 进链接边界 | 对齐 Alacritty/WezTerm/Ghostty，利于企业与远程 | 放弃 GPL 强制回馈，须自建贡献激励 |
| D8 | 把**模型**当供应链：权重哈希、prompt 模板、分发通道签名可追溯 | 模型是不可信执行体与投毒面 | 需维护签名与离线校验设施 |
| D9 | PTY/VT/Escape 解析器是第一类不可信输入，须内存安全 + 持续 fuzz | 终端漏洞多出在转义序列解析 | CI 算力与维护成本 |
| D10 | 危险动作双重确认**不可由配置关闭**（企业只能加强） | 不可逆损害无法事后补偿 | 与"一键全自动"正面冲突，最大冲突点 |

## 三、详细设计

### 3.1 威胁模型（STRIDE + 攻击树）

| 威胁 | 典型场景 | 缓解 |
|---|---|---|
| Spoofing | 插件冒充官方、伪造模型端点 | 签名 + 发布者身份；端点证书固定 |
| Tampering | 篡改审计日志或插件更新 | 哈希链 + 离线签名 + TUF 更新元数据 |
| Repudiation | "是 AI 自己删的库" | 不可抵赖审计链（人/插件/模型 + 审批人） |
| Info Disclosure | scrollback 中 token 被上传或进入 prompt | 出站分类闸门 + 脱敏管线 + 默认本地 |
| DoS | 超长行/恶意 ANSI 打爆解析或渲染 | 解析配额、内存上限、fuzz 回归 |
| Elevation | 插件越权读文件、出网、调 shell | capability token、默认拒绝、进程隔离 |

攻击树 Top3：① 提示注入诱导 AI 读 `.env` 拼进 `curl` 外传；② 插件窃取 kubeconfig/SSH agent；③ 供应链投毒致全量失陷。收口 §3.2/§3.3。

### 3.2 AI 执行命令的黄金规则（强制、不可关闭）

1. **能力与意图分离**：模型只产出结构化意图（tool + args），不产出可执行字符串，命令由确定性执行器构造。
2. **禁止 `shell -c` 拼接**：统一 argv 数组 + 显式转义。
3. **默认 dry-run**：先展示命令、影响面（读/写/网络/提权）与目标主机/路径。
4. **危险动作逐条批准**：破坏性、外发型、提权、跨主机操作不得整类"永远允许"。
5. **污点追踪**：不可信来源的值不得直接成为命令参数或路径，须转义并标注来源。
6. **最小权限执行**：AI 子进程默认无网络、只读 FS 白名单、不转发 SSH agent；提权到期回收。
7. **可回滚**：写操作前置快照，支持"撤销上次 AI 操作"。

### 3.3 脱敏与密钥管理

- 密钥存 OS keychain（Windows DPAPI/CredMgr、macOS Keychain、Linux Secret Service；无桌面用 libsodium 加密文件并告警）；内存 `mLock` + `zeroize`。
- **出站分类闸门**：发往模型/云的数据先过检测器——正则（PEM、`AKIA*`、`ghp_*`、JWT、连接串）+ 熵检测 + keychain 值反向匹配，命中则替换占位符或拒绝。
- 脱敏统一在上下文构建器实现，不依赖模型自律；本地模型同样脱敏；提供"敏感会话禁 AI"。

### 3.4 数据分类与审计

| 等级 | 数据 | 默认处理 |
|---|---|---|
| L0 公开 | 版本、帮助文本 | 可上传 |
| L1 内部 | 命令名、错误码（脱敏后） | opt-in 遥测 |
| L2 敏感 | 路径、源码、主机名、业务日志 | 默认本地，不出设备 |
| L3 机密 | 凭据、私钥、token、客户数据 | 从不入 prompt/日志/遥测 |

审计条目：操作者（人/插件/模型）、工具、脱敏参数、决策摘要、审批人、结果与时间；链式哈希防篡改、版本化，可推 SIEM。

### 3.5 供应链、SDLC 与合规

- 流水线：`cargo-deny`/`cargo-audit` + `npm audit` + CycloneDX SBOM；cargo-fuzz 覆盖 VT/PTY，种子取自真实流量；季度渗透测试。
- 漏洞 SLA：Critical 24h、High 7 天、Medium 30 天；公开安全公告与 CVE。
- 合规：GDPR（最小化、DSAR、DPIA）、SOC2（审计链、访问控制、变更管理）、企业 MDM 策略（macOS profile / Windows ADMX / Linux 文件式，可离线校验）、数据驻留。
- 许可：核心 Apache-2.0/MIT；依赖白名单禁 GPL/AGPL 进链接边界；插件市场强制 SPDX 扫描。

## 五、被否决的方案与反方意见

1. **"WASM 即安全沙箱"**：否决为唯一边界；反方（插件生态）称进程隔离伤性能——我接受。
2. **"AI 全自动执行、事后撤销"**：否决，不可逆损害无法撤销；反方（体验）称审批摩擦杀死卖点——我坚持默认审批 + 显式白名单升级。
3. **"scrollback 云同步默认开启"**：否决，默认本地；反方（协作）称跨设备体验受损——允许 opt-in 且 E2E 加密，服务端不可读。
4. **"正则脱敏足够"**：否决，须叠加熵检测与 keychain 反向匹配并接受误报。
5. **"单 GPL 许可换生态回馈"**：否决，企业采用与托管形态代价过大。

## 六、风险与缓解

| 风险 | 影响 | 缓解 | 残余风险 |
|---|---|---|---|
| 提示注入绕过 | 外泄/执行 | 能力分离 + 污点追踪 + 审批 | 新型注入，需持续红队 |
| 审批疲劳 | 用户盲批 | 风险分级 + 白名单 + 可解释提示 | 用户仍可能盲目批准 |
| 脱敏漏检 | secret 外泄 | 多层检测 + keychain 反向匹配 | 未知格式 secret |
| 插件供应链投毒 | 大规模失陷 | 签名 + TUF + 权限最小化 | 维护者密钥被盗 |

## 七、可验证验收标准

1. 100% 出站请求经分类闸门；以 50 个真实 secret 样本（PEM/JWT/云 token/连接串）测试，泄露率 **0**。
2. 危险动作（删除/外发/提权）**100%** 触发审批，且无法通过配置关闭。
3. VT/PTY 解析器 fuzz **≥ 10⁸ 次执行无崩溃**，历史 crash 全部回归。
4. 审计日志篡改检测：任意单字节修改均可发现，验证用例覆盖率 100%。
5. 默认配置下抓包：**零** 用户未发起的外部连接；遥测关闭时上传 0 字节。
6. SBOM 中处于链接边界的 GPL/AGPL 依赖数为 **0**。
7. 漏洞响应：Critical 24h 缓解率 ≥ 95%，High 7 天修复率 ≥ 90%。
8. 插件隔离：恶意插件越权读 SSH key 或发网络，拦截率 **100%**。

## 八、待决议问题

1. **审批粒度**：逐条确认 vs 风险分级 + 会话白名单？分级规则由谁定义？（与 Agent/体验冲突，需仲裁）
2. **远程/云形态**：是否提供托管模型与团队同步？E2E 加密与服务端可观测性边界在哪？
3. **企业策略强度**：企业能否禁止本地模型、强制上传审计至 MDM？与"本地优先"如何裁决？
4. **插件信任根**：自建 CA、平台签名还是 Web-of-Trust？吊销与离线如何处理？
5. **许可**：Apache-2.0 单许可 vs MIT 双许可；插件市场是否强制开源条款？
6. **脱敏失败默认动作**：拒绝发送（安全优先）还是脱敏后发送（体验优先）？我主张**拒绝并告知**。
