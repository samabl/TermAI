# TermAI 后端 / 云平台架构师评审意见

## 一、角色立场与判断依据

我的核心立场只有一句：**本地优先，云为增强（Local-first, Cloud-as-Enhancement）**。终端是用户最后的信任边界 —— 里面跑着生产凭据、私钥、客户数据。任何"为了 AI 体验默认上传终端上下文"的方案，在我这里一票否决。

判断依据三条：

1. **信任经济学**：终端产品的迁移成本来自"我敢不敢把生产环境交给它"。云能力带来的是线性收益，一次数据事故带来的是指数级品牌损失。
2. **可用性分层**：终端必须 100% 离线可用。云只承载"可降级"能力（跨设备同步、团队协作、托管模型）。断网、厂商宕机不得影响 ssh 与本地 shell。
3. **成本结构**：终端用户量大、单用户价值低于 IDE/SaaS。控制面必须薄且无状态；任何"每会话常驻服务端连接"的设计都会吃光毛利。

## 二、关键结论

**D1 云端只做控制面，不做数据面。** 结论：PTY 字节流、文件内容、命令输出、密钥材料永不进入我方服务端，除非用户显式开启共享会话/云沙箱。理由：信任边界 + 成本。代价：协作/远程协助必须走 P2P/WebRTC + 中继，实现更重；我们会比竞品少一批"开箱即云"的便利功能。

**D2 AI 网关只做路由与计量，不做内容中介。** 结论：默认 BYO-Key 直连厂商（我方仅下发短期凭证与路由决策）；只有"托管额度"通道经我方转发，且 UI 明示。理由：少一跳延迟、隐私、供应商可替换。代价：BYO 通道我方无法可信计量 token，配额只能依赖客户端上报（可伪造）→ 计费只认托管通道，BYO 不计费；跨用户 prompt 缓存命中率大幅下降。

**D3 身份 OIDC-first，设备码（RFC 8628）为主登录路径。** 结论：桌面/CLI 一律走设备码 + 浏览器授权，本地签发的 Ed25519 许可证 JWT 离线可验，无强制在线心跳。企业版接 OIDC SSO + SCIM 2.0。理由：不锁死自建身份系统，企业可自带 IdP。代价：设备码体验比一键浏览器回调多 10~20 秒，会被 UX 角色反对；离线许可证意味着无法实时封禁，只能靠短期 refresh + 吊销列表拉取。

**D4 同步只覆盖小文档，不默认同步历史。** 结论：设置、主题、片段、工作区元数据用 CRDT（LWW-Element-Set + 逻辑时钟）；命令历史与完整会话默认仅本地，跨端可选且端到端加密。理由：历史体积大、隐私高、冲突解决价值低。代价：同一功能在不同端表现不一致，用户会困惑；"换机即恢复"体验弱于竞品。

**D5 插件市场静态优先 + 透明签名日志 + 本地强制能力清单。** 结论：分发走 CDN 上的签名清单，动态 API 只负责发布/审核/统计；Ed25519 分离签名 + append-only 透明度日志（Sigstore/Rekor 思路）保证可审计与可远程吊销。理由：静态分发近乎零边际成本、CDN 天然抗压。代价：下架/热修有延迟，恶意插件第一小时无法即时阻断，需要客户端强制版本/哈希吊销检查兜底。

**D6 协议统一 Connect（gRPC + JSON 双栈），流式默认 SSE。** 结论：客户端与云之间用 Connect/HTTP，单向 token 流用 SSE，WebSocket 仅用于双向协作/终端共享；内部服务走 gRPC。理由：SSE 可穿透企业代理、天然可重连带 Last-Event-ID、易做 CDN。代价：双向场景仍需 WS，等于维护两套流式语义；gRPC-web 在部分老代理上仍需降级路径。

**D7 遥测默认关闭（opt-in），崩溃报告独立开关，内容零采集。** 结论：禁止采集命令文本、路径、代码、域名；只用本地聚合计数 + 采样。理由：终端遥测一旦越界即公关灾难。代价：产品决策数据稀疏，A/B 与留存分析能力显著弱于同类，PM 会强烈反弹。

**D8 存储与部署单区起步。** 结论：Postgres（RLS 多租户）+ Redis（限流/会话）+ S3 兼容对象存储（插件包/归档）+ ClickHouse（计费与遥测事件，可延后），部署在单一 region 的托管 K8s/Fly.io；AI 网关为靠近用户的 edge 无状态服务。理由：控制面写入量小，多区一致性是纯负担。代价：跨洋用户控制面延迟 150ms+，需靠本地缓存与乐观 UI 掩盖。

**D9 许可采用 Open Core。** 结论：本地单机客户端内核 Apache-2.0；云、团队协作、企业能力用 BSL 1.1（4 年后自动转 Apache-2.0）；插件市场抽成 15%~20%。理由：单机开源赢得信任与插件生态，云端闭源保住收入。代价：会被开源社区批"开放核心"、可能被竞品 fork 出免费云；BSL 阻止不了打包分发，只能阻止托管竞争。

**D10 企业租户强隔离。** 结论：默认 shared DB + RLS，企业档提供独立 schema/DB + per-tenant KMS 密钥 + 数据驻留（EU/US）选择。理由：合规是付费点。代价：多形态部署让 schema 迁移与运维复杂度翻倍，必须从第一天就把 tenant 维度写进每个查询与索引。

## 三、详细设计

**服务拆分（控制面）**：Auth/Identity、Entitlement（许可证与权益）、Sync、AI Gateway、Plugin Registry、Telemetry Ingest、Billing/Metering、Admin/SCIM。每个服务独立无状态，共享 Postgres 与 Redis。

**本地与云的边界**

| 能力 | 必须本地 | 可上云 |
|---|---|---|
| PTY/VT 解析/渲染 | 是 | 否 |
| 命令历史、会话内容 | 默认本地 | 仅端到端加密的可选备份 |
| API Key / Secret | OS Keychain | 否（企业 KMS 仅托管我方凭证） |
| 模型调用 | 直接出网可选 | 路由/计量/托管额度 |
| 设置/片段 | 本地 SQLite 主副本 | 增量 CRDT 同步 |
| 插件执行 | 本地沙箱 | 仅分发与统计 |

**API 规范**：proto-first，用 Buf 管理；v1 路径与包级版本化；错误用 Connect 标准 code + 机器可读 reason；写接口支持 Idempotency-Key；列表一律 cursor 分页；限流按 tenant+device 双维度（Redis 令牌桶）。SSE 事件带 id/event/data，支持 Last-Event-ID 断点续传。

**数据模型要点**：tenant → user → membership(role) → device(public key)；entitlement 由许可证 JWT 派生；plugin / plugin_version(manifest_hash, sig, yanked) / installation；sync_document(tenant, doc_id, crdt_state, version_vector)；usage_event(append-only, 幂等键)；ai_request_log 只存元数据（provider、token 数、延迟、状态），**不存 prompt 与 completion**。

**离线优先与冲突**：本地 SQLite 为唯一真源；出站队列（outbox）+ 幂等重放；CRDT 文档用版本向量，墓碑 + 周期性 compaction 控制体积；服务端除业务校验外不做自动合并；同一 doc 并发写按逻辑时钟 LWW，语义冲突交 UI 提示。冲突解决策略必须可解释、可回滚。

**多租户与隔离**：所有表带 tenant_id，Postgres RLS 强制；连接池按 tenant 绑定会话变量；跨租户查询在 repository 层静态禁止（CI 静态检查 + 集成测试）。

**可观测性**：OpenTelemetry trace 贯穿客户端→网关→厂商（客户端侧脱敏采样）；SLO 看板；日志结构化且默认不落 PII，保留 30 天；计费事件单独走 ClickHouse，保留 13 个月。

**部署与成本模型**：单 region K8s（可选托管）起量；CDN 承载插件分发；AI 网关按请求计费 + 供应商批量折扣。成本红线：控制面单 MAU 月成本 < 0.05 美元；托管模型通道毛利 > 25%。

## 四、与其他角色的接口与依赖

**我需要别人给我：**
- 内核/渲染角色：稳定的**结构化事件总线 schema**（session/command/fs/git 事件）+ 命令边界（exit code、cwd、耗时），否则 AI 与云端的上下文建模全部落空。
- 安全角色：威胁模型、密钥存储方案（OS Keychain/TPM）、签名与吊销规范。
- 前端架构：设备码与回调用例、离线状态机与乐观更新契约。

**我向别人承诺：**
- 向 AI/Agent 角色：统一 Provider 抽象（OpenAI/Anthropic/Gemini/本地 Ollama 同一接口）、token 流协议、配额查询 API、失败降级策略；承诺网关 p95 附加延迟 < 120ms。
- 向 UX：登录 ≤ 30s、同步 p95 ≤ 300ms、离线功能 100% 可用。
- 向插件生态：发布审核 SLA（自动扫描 ≤ 10 分钟）、签名与统计 API、远程吊销 ≤ 1 小时生效。
- 向财务/商业：可审计的计费口径与成本看板。

## 五、被否决的方案与反方意见

| 被否决方案 | 反方（支持方）理由 | 我否决的代价 |
|---|---|---|
| 服务端 PTY（全云终端） | 跨端一致、零本地依赖 | 延迟不可接受、成本爆炸、信任崩塌 |
| Electron/Node 直连云、密钥下发前端 | 开发最快 | 密钥必泄，合规不可过 |
| WebSocket 承载全部终端流 | 双向、易实现 | 无法经受企业代理与规模成本 |
| 服务端保存 prompt 用于训练 | 数据飞轮、评测增强 | 隐私红线，企业客户直接出局 |
| 自建账号体系 | 掌控力强 | 企业 IdP 接入受阻，安全负担自负 |
| 纯 AGPL 全开源 | 社区口碑、防云厂商吸血 | 无法支撑团队/企业收入 |
| 强一致多区控制面 | 全球低延迟 | 复杂度与成本远超收益 |

预期冲突点（请仲裁关注）：与**内核/渲染角色**在"结构化事件总线是否过度抽象、伤性能"；与 **AI/Agent 角色**在"不落 prompt 导致无法做云端评测与跨用户缓存"；与 **UX 角色**在"设备码登录体验"；与**开源策略角色**在 Open Core 边界；与**隐私/安全角色**在"插件远程吊销与遥测 opt-in"。

## 六、风险与缓解

| 风险 | 概率/影响 | 缓解 | 触发信号 |
|---|---|---|---|
| BYO 通道配额被伪造 | 高/中 | 只对托管通道计费；客户端上报仅作 UI 展示 | 计费对账差异 > 2% |
| 供应商 API 变更/涨价 | 高/高 | Provider 抽象 + 灰度切流 + 多供应商 | 单供应商错误率 > 5% |
| 同步 CRDT 文档膨胀 | 中/中 | compaction、体积配额、历史截断 | 单 doc > 1MB |
| 多租户越权 | 低/致命 | RLS + 静态检查 + 渗透测试 | 出现跨租户访问告警 |
| 控制面宕机影响本地 | 中/高 | 客户端全离线降级、无阻塞启动 | 客户端启动依赖云调用 |
| 插件供应链攻击 | 中/高 | 签名 + 透明度日志 + 能力清单 | 签名校验失败率异常 |
| Open Core 被 fork 托管 | 中/中 | BSL 时间窗 + 企业差异化能力 | 出现第三方托管 |

## 七、可验证验收标准

1. 断网（拔网线）下，本地终端、AI（BYO + 本地模型）、插件全部可用；启动不产生任何阻塞式云调用。
2. AI 网关热路径附加延迟 p95 < 120ms、p99 < 300ms；单供应商故障 2s 内自动切流。
3. 设置同步端到端 p95 < 300ms、p99 < 1s；冲突合并结果 100% 可解释并可回滚。
4. 设备码登录全流程（发起到拿到 token）≤ 30s，失败可重试且不产生僵尸设备记录。
5. 跨租户越权测试用例 0 通过；RLS 覆盖率 100%（所有含 tenant_id 的表）。
6. 服务端代码库中 prompt/completion 字段出现次数 = 0（CI 静态禁止）。
7. 插件从提交到可下载 ≤ 10 分钟；吊销到客户端生效 ≤ 1 小时（p95）。
8. 控制面可用性 ≥ 99.9%，AI 网关 ≥ 99.5%（不含上游厂商责任期）。
9. 控制面单 MAU 月成本 ≤ 0.05 美元，托管模型通道毛利 ≥ 25%。
10. 遥测默认关闭；开启后上报数据经 schema 校验且 0 字段含命令/路径/内容。

## 八、待决议问题（Open Questions）

1. **Open Core 边界**：AI 网关本身开源还是闭源？开源获信任、闭源保收入，是否存在第三种（开源协议 + 商业托管许可）？
2. **托管模型是否长期投入**：若 BYO 占 90%，是否值得自建转发与计费体系？还是只做企业版统一网关？
3. **跨端同步范围**：命令历史云端可选加密备份是否值得做（体积/成本/隐私三重压力）？
4. **数据驻留粒度**：EU/US 双区是租户级还是文档级？后者成本高一个量级。
5. **团队协作传输层**：WebRTC P2P + TURN 中继成本 vs 服务端中继的隐私代价，谁拍板？
6. **插件市场抽成与审核投入**：抽 15% 是否覆盖人工审核与法务成本？是否需要"人工审核仅限高权限插件"的分级？
7. **遥测 opt-in 的数据代价**：是否接受用社区调研替代产品分析，从而在数据驱动上系统性落后？
8. **企业私有化部署形态**：是否提供自托管控制面？如果提供，SLA 与支持模型如何定义？
